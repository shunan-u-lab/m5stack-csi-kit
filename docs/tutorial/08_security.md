# 8. 安全の仕組み — 鍵・署名・合言葉と、守れないこと

[目次](README.md) ・ 前: [7. 困ったとき・用語集](07_troubleshooting_glossary.md)

この章のゴール: **「このキットは、誰が無線で命令を送れるかを鍵で守っている。でも、電波そのものから測られることは防げない」**と
自分の言葉で説明できること。そして、守るための計算（HMAC）と、それを担当するコードの場所が分かること。

実機は要りません（3 章で組ませた後なら、8-3 の確かめを実機でも見られます）。

---

## 8-1. 何を守るのか — 「玄関の鍵」と「カーテン」

🌱 **ファーストタッチ**

家の安全には、2 つの別々のものがあります。**玄関の鍵**は、知らない人が入ってきて家の中を勝手にいじるのを防ぎます。
**カーテン**は、外から中をのぞかれるのを防ぎます。玄関に鍵をかけても、カーテンを開けたままなら外から見えます。

このキットにも同じ 2 つがあります。

- **玄関の鍵にあたるもの:** 受信機は、無線で送信機に「チャンネルを変えて」「出力を下げて」と命令できます。
  知らない人が同じ命令を送ってきても、送信機は従いません。**これは守っています**
- **カーテンにあたるもの:** 送信機は 1 秒に 100 回電波を出し続けます。その電波は部屋の外にも漏れ、**他人も CSI を測れます**。
  **これは守れません**（カーテンが無い）。だから、記録しないときは送信機の電源を切ります

🌿 **しくみ**

| 心配なこと | このキットで | どうやって |
|---|---|---|
| 他人が偽の命令で、チャンネル・出力を勝手に変える | **防ぐ** | 命令に**署名**を付け、鍵を持つ相手の命令だけを受け付ける（8-3） |
| 他人が、前に送られた本物の命令を録音して流し直す | **ほぼ防ぐ** | 命令に**合言葉**を入れ、合言葉は使うたびに変わる（8-4） |
| 誰かが偽の命令を送ってきたことに気づく | **気づける** | 署名の合わない命令を数え（`ctrl_bad`）、送信機の表示に毎秒出す |
| 他人が電波から部屋の様子を測る | **防げない** | 送信機の出力を下げると届く範囲が狭まるだけ。**電源を切るのがいちばん効く** |
| パケットの中身をのぞかれる | 防いでいない | 中身は連番・時刻・合言葉だけ。秘密の情報は載せていない |
| 電波の妨害 | 防げない | 無線では一般に防げない |
| M5Stack Basic そのものを持っていかれる | 防げない | M5Stack Basic の中の鍵は読み出せる。人に渡す前に組を消す（8-5） |

🌳 **もう一段** — 守る仕組みは、どのファイルにあるの？

> この節は、**今は分からなくても先へ進んでかまいません**。

**まず、たとえで全体を見ます。** 玄関の鍵は「錠前（ドアに付いている部分）」と「合鍵（持ち歩く部分）」でできています。
このキットでは、錠前にあたる計算がファームウェアの中に、合鍵を作って配る係が PC 側にあります。

**次に、自分の目で確かめます。** 担当するファイルを開いて、先頭の説明だけ読んでみます。

| 役目 | ファイル |
|---|---|
| 署名を作る・確かめる計算（錠前） | `firmware/shared/CsiAuth/src/CsiAuth.h` |
| 組（相手の MAC と鍵）を M5Stack Basic に置く・読む | `firmware/shared/CsiPair/src/CsiPair.h` |
| 鍵を作って両方の M5Stack Basic に配る（合鍵を作る係） | `src/csikit/pairing.py` |
| なぜこの形にしたか（設計の記録） | [ADR 0002](../decisions/0002-peer-mac-and-key-in-nvs.md)・[ADR 0005](../decisions/0005-control-auth-and-tx-power.md) |

**分かったこと**

- 守っているのは「命令」で、「電波」ではない。この 2 つを分けて考えると、何ができて何ができないかが見える

**今は分からなくてよい所:** C++ の書き方。ADR の細かい数字。

## 8-2. 組（ペア）と鍵 — 「Bluetooth のペアリング」

🌱 **ファーストタッチ**

ワイヤレスイヤホンを初めて使うとき、スマホと**ペアリング**します。一度ペアリングすると、
イヤホンは自分のスマホとだけつながり、隣の人のスマホとはつながりません。

このキットの送信機と受信機も、`csikit flash` のときに**組（ペア）**になります。組になった 2 台は、
**お互いの名前（MAC アドレス）と、2 台だけが知っている秘密の値（鍵）**を覚えます。

🌿 **しくみ**

- 鍵は、組ませるたびに PC が**新しく乱数で作ります**。同じキットでも、組ませ直すと鍵は変わります
- 鍵は、両方の M5Stack Basic の中の「設定の置き場」（NVS。スマホの「設定」アプリのようなもの）にだけ置かれます。
  **このリポジトリにも、配っている `.bin` にも、鍵は入っていません**。だから、`.bin` を他の人と共有しても安全です
- 鍵は**画面にもログにも出しません**。`csikit` は、鍵を送った行や M5Stack Basic の返事を表示しないように作ってあります
- 組が無い M5Stack Basic は、無線の命令を**一切受け付けません**（液晶に黄色の `NOT PAIRED`）。「分からないときは閉じておく」側に倒してあります

🌳 **もう一段** — 鍵はどのくらい当てにくいの？

> この節は、**今は分からなくても先へ進んでかまいません**。

**まず、たとえで全体を見ます。** スマホの 4 桁の暗証番号は、0000〜9999 の 1 万通りです。
このキットの鍵は 16 バイト、つまり 0 と 1 が 128 個並んだ値です。何通りあるかを数えます。

**次に、自分の目で確かめます。** 鍵の通りの数と、鍵を作るときの長さを確かめます（鍵そのものは表示しません）。

```sh
uv run python -c "print(2 ** 128)"
uv run python -c "from csikit import pairing; print(len(pairing.new_key()))"
```

1 行目は約 3.4 × 10³⁸（340 澗）、2 行目は `32`（16 バイトを 16 進数の文字で書くと 32 文字）と出れば正解です。

**式で書くと:**

- 鍵の通りの数 = 2¹²⁸ ≈ 3.4 × 10³⁸。4 桁の暗証番号（10⁴ 通り）の約 3 × 10³⁴ 倍

**分かったこと**

- 鍵は総当たりでは当てられない。弱点になるのは「鍵の数」ではなく、**鍵を人に見られること・M5Stack Basic ごと持っていかれること**（8-5）

**今は分からなくてよい所:** 乱数の作り方（Python の `secrets`）。NVS の中の並び。

## 8-3. 署名 — 「書類の印鑑」

🌱 **ファーストタッチ**

役所に出す書類には印鑑を押します。書類の中身が同じでも、印鑑が無ければ受け付けてもらえません。
そして、印鑑は本人しか持っていないので、他人は本人になりすまして書類を出せません。

受信機が送信機に出す命令（「チャンネルを 6 にして」など）にも、**署名**という印鑑を付けます。
送信機は署名を確かめ、合わなければ命令を捨てます。

🌿 **しくみ**

- 署名は、**命令の中身と鍵から計算した 8 バイトの値**です。鍵を持っていないと、正しい署名を作れません
- 中身が 1 文字でも違えば、署名はまったく別の値になります。だから「本物の命令の一部だけ書き換える」こともできません
- 送信機の「了解」の返事にも署名を付けます。偽の「了解」で受信機だけを別のチャンネルへ動かす手口も防ぎます
- 署名の合わない命令は数えて（`ctrl_bad`）、送信機の表示に毎秒出します。急に増えたら、誰かが試しているかもしれません

🌳 **もう一段** — 署名はどう計算するの？

> この節は、**今は分からなくても先へ進んでかまいません**。

**まず、たとえで全体を見ます。** 「中身」と「鍵」を混ぜてかき回す、元に戻せないミキサーがあると考えます。
同じ中身と同じ鍵なら、いつも同じ結果が出ます。中身か鍵のどちらかが少しでも違うと、結果はまったく違うものになります。
結果から鍵を逆算することもできません。このミキサーを **HMAC**（エイチマック）と言います。

**次に、自分の目で確かめます。** 練習用の鍵（全部 0 の、本物ではない鍵）で、命令の署名を計算してみます。

```sh
uv run python -c "import hmac, hashlib; key = bytes(16); print(hmac.new(key, b'CH 6', hashlib.sha256).hexdigest()[:16])"
uv run python -c "import hmac, hashlib; key = bytes(16); print(hmac.new(key, b'CH 7', hashlib.sha256).hexdigest()[:16])"
```

`CH 6` と `CH 7` の 1 文字の違いで、16 文字（8 バイト）の署名がまったく別の値になります。
実物の命令は文字ではなく 16 バイトの決まった並び（命令の種類・チャンネル・番号・合言葉）ですが、計算は同じです。

**式で書くと:**

- 署名 = HMAC-SHA256(鍵, 命令の中身) の先頭 8 バイト
- 鍵を知らない人が当てずっぽうで署名を付けて、たまたま合う確率 = 1 / 2⁶⁴ ≈ 5 × 10⁻²⁰
- 1 秒に 1,000 回試し続けても、合うまでの時間の目安は約 2.9 億年（計算: 2⁶⁴ ÷ 1000 ÷ 2 秒）

```sh
uv run python -c "print(2 ** 64 / 1000 / 2 / 3600 / 24 / 365)"
```

約 2.9 × 10⁸（2.9 億）と出れば正解です。

**分かったこと**

- 署名があると、鍵を持つ相手の命令だけが通る。送り元の名前（MAC）は偽れるが、署名は偽れない

**今は分からなくてよい所:** SHA-256 の中身。比べるときに時間の差で手がかりを与えない書き方
（`CsiAuth.h` の `verify` は、1 バイトずつ全部比べてから結果を出す）。

> 実機で見るなら（3 章の後）: 送信機の USB の表示に、1 秒ごとに `ctrl_rx=`（受け付けた命令の数）と `ctrl_bad=`（署名の合わない命令の数）が出ます。
> 2026-10-28 の試験では、送信機にだけ別の鍵を入れると、受信機の `CH 6` は `reason=tx_no_ack` で失敗し、送信機は元のチャンネルのままでした
> （[試験の記録](../test-log/2026-10-28-kit-firmware-flash-and-pair.md)）。

## 8-4. 合言葉 — 「SMS の認証コード」

🌱 **ファーストタッチ**

ネットのサービスにログインするとき、スマホに 6 桁の**認証コード**が届くことがあります。
このコードは 1 回しか使えません。誰かが盗み見ても、次のログインでは別のコードになるので使えません。

署名だけだと、困ることが 1 つあります。誰かが**本物の命令を録音しておき、後で流し直す**と、署名も本物なので通ってしまいます。
そこで、命令に**合言葉**を入れます。合言葉は送信機が決め、命令を受け入れるたびに変えます。

🌿 **しくみ**

- 送信機は、1 秒に 100 回送るパケットに、今の合言葉（起動ごとの乱数）を載せています
- 受信機は、命令を出すときに、その合言葉も含めて署名します
- 送信機は、命令を受け入れたら合言葉を変えます。録音された古い命令は、古い合言葉で署名されているので通りません
- 例外: 受信機の命令が送信機に**届かなかった**とき、それを録音した人が合言葉の変わる前に流し直すと、遅れて実行されます。
  ただし中身は本物の命令（受信機が出そうとしたもの）なので、害は小さいと判断しています

🌳 **もう一段** — 同じ命令でも、合言葉が変わると署名は変わる？

> この節は、**今は分からなくても先へ進んでかまいません**。

**まず、たとえで全体を見ます。** 8-3 のミキサーに入れる「中身」に、合言葉も一緒に入れます。
命令が同じでも、合言葉が違えば結果（署名）は別の値になります。

**次に、自分の目で確かめます。** 練習用の鍵で、合言葉だけを変えた同じ命令の署名を比べます。

```sh
uv run python -c "import hmac, hashlib; key = bytes(16); [print(n, hmac.new(key, b'CH 6 nonce=' + n, hashlib.sha256).hexdigest()[:16]) for n in (b'1111', b'2222')]"
```

同じ `CH 6` でも、合言葉 `1111` と `2222` で署名が別の値になります。送信機は今の合言葉で確かめるので、古い合言葉の命令は合いません。

**式で書くと:**

- 署名 = HMAC-SHA256(鍵, 命令 ∥ 合言葉) の先頭 8 バイト（∥ はつなげる、の意味）
- 録音した命令が有効な期間 = 次の命令が受け入れられるまで（原則 1 回きり）

**分かったこと**

- 署名で「誰が出したか」を、合言葉で「今出されたものか」を確かめている

**今は分からなくてよい所:** 合言葉の作り方（`firmware/csi-tx/src/main.cpp` の `rotate_nonce`）。命令の番号（token）と了解の対応づけ。

## 8-5. 守れないことと、自分でできること

🌱 **ファーストタッチ**

スマホにロックをかけていても、画面を人に見せればのぞかれますし、スマホごと渡せば中身は見られます。
道具の安全は、**使う人のふるまい**とセットです。

🌿 **しくみ** — 自分でできること

| すること | 理由 |
|---|---|
| **記録しないときは、送信機の電源を切る** | 電波が出ていなければ、誰にも測られない。いちばん効く |
| M5Stack Basic を人に渡す・返す前に、組を消す（2 台ともつないで `uv run csikit unpair`） | 鍵は M5Stack Basic の中に**暗号化せずに**置いてある。M5Stack Basic を手にした人は読み出せる |
| 鍵を見られた・M5Stack Basic をなくしたかもしれないときは、組ませ直す（`uv run csikit flash --pair-only`） | 鍵が新しくなり、古い鍵は使えなくなる |
| 鍵・`PAIRSET` の行を、画面・スクリーンショット・AI への質問に貼らない | 鍵が漏れると、署名の守りが無くなる |
| 受信機の Wi-Fi のパスワードは、入力か環境変数で渡す（README の「書き込んで組ませる」） | ファームやリポジトリにパスワードを残さない |
| 記録・周りの Wi-Fi の名前（SSID）・機器の識別子（MAC・BSSID）を人に見せるときは伏せる。記録は `scripts/mask_macs.py` で MAC をダミーにした写しを渡す | 場所や人を特定する手がかりになる（1-6） |
| 吸い出した `.bin`（`scripts/backup_flash.py`）は人に渡さない | 中に鍵と Wi-Fi のパスワードが入っている |

**守れないこと（このキットでは対策していない）**

- 電波から CSI を測られること（8-1）
- 電波の妨害、偽の命令を大量に送りつけられること（大量に来たときの負荷は測っていない）
- USB でつなげる人は、シリアルから何でも操作できる（物理的に触れる人を限る）
- ESP32 のフラッシュの暗号化・セキュアブート（起動するプログラムの検査）は使っていない

🌳 **もう一段** — 電波の届く範囲は、出力を下げるとどれくらい狭まる？

> この節は、**今は分からなくても先へ進んでかまいません**。

**まず、たとえで全体を見ます。** 声を小さくすると、聞こえる範囲は狭まります。でも、ゼロにはなりません。
送信機の出力も下げられますが（`uv run csikit txpower <dBm>`。受信機が送信機に無線で伝える）、届く範囲が狭まるだけです。

**次に、自分の目で確かめます。** 出力を 8.5 dB 下げたとき、届く距離が何倍になるかを計算します
（屋内で、受ける強さが距離の 3 乗で弱まると**仮定**します）。

```sh
uv run python -c "print(10 ** (-8.5 / 30))"
```

約 `0.52` と出れば正解です。距離がおよそ半分、面積ではおよそ 4 分の 1 になります。

**式で書くと:**

- 距離の比 = 10^(下げた dB ÷ (10 × n))。n は弱まり方の指数（屋内で 2〜4 程度。ここでは 3 と仮定）
- n = 3 のとき、8.5 dB 下げると 10^(−8.5/30) ≈ 0.52

**分かったこと**

- 出力を下げても範囲は狭まるだけ。測られたくないときは、電源を切る

**今は分からなくてよい所:** 電波の弱まり方のモデル（実際の値は部屋によって違い、このキットでは**測っていない**）。

## 確かめよう

1. 玄関の鍵とカーテンのたとえで、このキットが「守っているもの」と「守れないもの」を 1 つずつ言える？
2. 8-3 の練習用の鍵で、`CH 6` の署名を 2 回計算すると、同じ値になる？　別の値になる？
3. M5Stack Basic を後輩に渡す前に、何をすればよい？
4. 記録しない夜のあいだ、送信機をどうしておくのがいちばん安全？

<details>
<summary>答え</summary>

1. 守っているもの: 偽の命令でチャンネル・出力を変えられること（玄関の鍵）。守れないもの: 電波から部屋の様子を測られること（カーテン）
2. 同じ値になる。中身と鍵が同じなら、HMAC はいつも同じ結果を出す（だから送信機が確かめられる）
3. 2 台ともつないで `uv run csikit unpair` を実行し、組（鍵）を消す。受け取った人は自分で `csikit flash` して組ませる
4. 電源を切る

</details>

## AI に聞いてみよう

- 「HMAC とは何か、スマホで身近な例を使って説明して。ただし、パスワードをそのまま保存するのと何が違うかも教えて」
- 「リプレイ攻撃（録音した命令の流し直し）を、ワンタイムパスワードの例で説明して」
- 「`firmware/shared/CsiAuth/src/CsiAuth.h` の `verify` が、1 バイトずつ全部比べてから結果を出すのはなぜ？」（コマンドライン AI なら、ファイルを開いて説明してもらう）

**AI に貼らないもの:** 鍵、`PAIRSET` の行、吸い出した `.bin`、周りの Wi-Fi の名前（SSID）や MAC。
