# 0. パソコンの基本 — ターミナル・uv・git・マイコン

[目次](README.md) ・ 次: [1. CSI とは](01_what_is_csi.md)

この章のゴール: **ターミナルを開き、このキットを手元に置き、`uv run csikit doctor` を動かせる**こと。
そして、その 1 行が裏で何をしているかを、ざっくり説明できること。

---

## 0-1. 登場するコンピュータは 3 台

🌱 **ファーストタッチ**

このキットでは、コンピュータが 3 台出てきます。

| もの | スマホでたとえると |
|---|---|
| パソコン（PC） | いつものスマホ。アプリをいくつも入れられ、画面で操作する |
| M5Stack Basic（送信機 T1） | **アプリが 1 つしか入らない小さなスマホ**。画面・ボタン・電池・Wi-Fi は付いている |
| M5Stack Basic（受信機 R1） | 同じ小さなスマホ。ただし入れるアプリが違う |

M5Stack Basic の中で動く「たった 1 つのアプリ」を **ファームウェア** と呼びます。
キットの準備とは、2 台の小さなスマホに、それぞれ「送る係のアプリ」「受け取る係のアプリ」を入れることです。

🌿 **しくみ**

- M5Stack Basic の中心は **マイコン**（マイクロコントローラ）です。この M5Stack Basic では ESP32 という部品で、Wi-Fi の無線も 1 つの部品に入っています
- マイコンには OS（Windows・iOS のような土台）がほぼ無く、電源を入れると、書き込まれた 1 つのプログラム（ファームウェア）がすぐ動き始めます
- ファームウェアを入れ替えることを **書き込み**（フラッシュ）と言います。スマホのアプリの入れ替えと違い、**前の中身は消えます**
- PC とマイコンは **USB ケーブル**でつなぎ、文字のやりとり（**シリアル通信**）で命令を送ったり、測った値を受け取ったりします

> たとえが当てはまらない所: スマホのアプリはタップで入れ替えられますが、マイコンへの書き込みには PC と専用の道具（esptool）が要ります。
> また、マイコンは「起動したら勝手に仕事を始め、電源を切るまで同じ仕事を続ける」ものです。

🌳 **もう一段** — ファームウェアは、どうやって M5Stack Basic に入るの？

> この節は、**今は分からなくても先へ進んでかまいません**。3 章で実際に書き込んだ後に読むと、分かりやすくなります。

**まず、たとえで全体を見ます。** 料理にたとえると、ファームウェアが M5Stack Basic に入るまでは 3 段です。

| 料理 | ファームウェア | このキットでは |
|---|---|---|
| **レシピ**（人が読む文章） | **ソースコード**。人が読み書きするプログラムの文章 | `firmware/csi-tx/src/main.cpp`（送信機）・`firmware/csi-rx/src/main.cpp`（受信機） |
| **調理**（レシピから料理を作る） | **ビルド**。ソースコードを、マイコンが実行できる形に変換する | PlatformIO という道具が行う |
| **料理を盛った皿**（そのまま出せる） | **`.bin` ファイル**。ビルドの結果を 1 つにまとめたもの | `csi-tx-m5stack-basic.bin`・`csi-rx-m5stack-basic.bin` |
| **配膳**（お客さんの前に置く） | **書き込み**。`.bin` を M5Stack Basic に入れる | esptool が行う（`csikit flash` が呼ぶ） |

このキットでは、調理（ビルド）は作者が済ませて、皿（`.bin`）を配っています。
だから**普段はレシピも調理道具も要らず、配膳（書き込み）だけで使えます**。レシピを変えたい人だけが、PlatformIO で自分で調理します。

**次に、レシピ（ソースコード）を少しだけのぞきます。** `firmware/csi-tx/src/main.cpp` をエディタで開き、`void setup` と `void loop` を探してください。
マイコンのプログラムは、この **2 つの決まった部分**が土台になっています。お店にたとえると:

| 部分 | お店で言うと | いつ動く |
|---|---|---|
| `setup()` | **開店準備**（電気を点ける・レジを開ける） | 電源を入れたとき **1 回だけ** |
| `loop()` | **営業**（お客さんの相手を繰り返す） | 開店準備の後、**電源を切るまでずっと繰り返す** |

送信機の `setup()` の中身は、次のようになっています（一部を抜き出し）。

```cpp
void setup() {
  led_init();          // 動作を知らせる LED の準備（M5Stack Basic には付いていないので、何も光らない）
  Serial.begin(SERIAL_BAUD);  // PC と文字で話す準備（速さを決める）
  delay(1000);         // 1 秒待つ
  setup_radio();       // 電波の準備（チャンネルなど）
  setup_auth();        // 組（相手と鍵）を読み込む
  report_config();     // 準備の結果を PC に報告する
  ...
```

`//` から右は、人のためのメモ（**コメント**）で、マイコンは読み飛ばします。この版の右側のメモは説明のために書き足したもので、実物のファイルにはありません。
上から順に「準備」が並んでいるのが分かれば十分です。`loop()` のほうは、**10 ミリ秒ごとにパケットを 1 つ送る**、を繰り返しています。

**分かったこと**

- 人が書くのはソースコード（レシピ）。マイコンが実行するのはビルドした結果（`.bin`）。キットの利用者は `.bin` を書き込むだけでよい
- マイコンのプログラムは「1 回だけの準備（`setup`）」と「ずっと繰り返す仕事（`loop`）」でできている

**今は分からなくてよい所:** C++ という言語の書き方（`void`・`;`・`{ }` など）、`#if` で始まる行、`loop()` の中の細かい処理。
ファームウェアを自分で変えたくなったときに、少しずつ読めば十分です。全体の説明は [送信機の README](../../firmware/csi-tx/README.md) にあります。

## 0-2. ターミナル — 文字で頼むアプリ

🌱 **ファーストタッチ**

スマホでは、アイコンをタップしてアプリを動かします。**ターミナル**は、タップの代わりに**文字で頼む**画面です。
チャットアプリで「〇〇して」と送ると返事が来るのに似ています。

- 1 行打って **Enter**（送信ボタン）を押すと、コンピュータが仕事をして、結果を文字で返してくる
- 返事が来るまで、次の行は打てない（打っても待たされる）

🌿 **しくみ**

ターミナルの開き方:

| OS | 開き方 |
|---|---|
| Windows | スタートボタンを押して「ターミナル」または「PowerShell」と打ち、出てきたものを開く |
| Mac | ⌘（command）+ スペースで検索を出し、「ターミナル」と打って開く |
| Linux（Ubuntu など） | Ctrl + Alt + T |
| Chromebook | 先に Linux 開発環境をオンにする（[付録](chromebook.md)）。その後、アプリの一覧の「ターミナル」→「penguin」 |

最初に覚えるのは 4 つだけです。

| 打つもの | 意味 | スマホでたとえると |
|---|---|---|
| `cd フォルダ名` | そのフォルダに入る | ファイルアプリでフォルダをタップする |
| `ls`（Windows の PowerShell でも使える） | 今のフォルダの中身を見る | フォルダの中を一覧で見る |
| `cd ..` | 1 つ上のフォルダに戻る | 「戻る」ボタン |
| Ctrl + C | 動いている仕事を止める | アプリを強制終了する |

- **今いるフォルダ**（カレントディレクトリ）がいつも決まっていて、命令はそこを基準に動きます。
  このキットの命令は、**キットのフォルダ（`m5stack-csi-kit`）の中で**打ちます
- ファイルの場所を表す文字列を **パス** と言います（住所のようなもの）。`docs/tutorial/README.md` は「docs フォルダの中の tutorial フォルダの中の README.md」

**エラーは、いちばん下から読みます。** 何行も赤い文字が出ても、たいてい最後の行に「何が困ったか」が書いてあります。

🌳 **もう一段**

- ターミナルの中で、打った文字を読んで仕事を振り分けているプログラムを **シェル** と呼びます（Windows は PowerShell、Mac・Linux は bash や zsh）。
  OS によって細かい書き方が違うので、このキットの説明は、どれでも同じに動く書き方を選んでいます
- `uv run csikit doctor` のような 1 行は、「`uv` というプログラムに、`run csikit doctor` という引数を渡す」という意味です。
  引数がどう読まれるかは、0-4 の 🌳 で追いかけます

## 0-3. uv — 「このキット専用の部屋」を用意する係

🌱 **ファーストタッチ**

スマホのアプリは、アプリストアから入れると、必要なものが勝手にそろいます。
このキットの PC 側のプログラムは Python という言語で書かれていて、動かすには Python 本体と、たくさんの部品（ライブラリ）が要ります。
**uv** は、それらを**アプリストアのように一度にそろえ**、しかも**このキット専用の部屋**にしまってくれる係です。
パソコンの他の場所はほとんど汚しません。

🌿 **しくみ**

uv の入れ方（それぞれのターミナルに 1 行を貼り付けて Enter。公式の手順: https://docs.astral.sh/uv/ ）:

```sh
# Mac・Linux
curl -LsSf https://astral.sh/uv/install.sh | sh
```

```powershell
# Windows（PowerShell）
powershell -ExecutionPolicy ByPass -c "irm https://astral.sh/uv/install.ps1 | iex"
```

入れた後は、**ターミナルを一度閉じて、開き直します**（新しく入れた道具の場所を、ターミナルが覚え直すため）。
`uv --version` と打って版が出れば入っています。

よく使う命令:

| 命令 | すること |
|---|---|
| `uv sync` | キットに要る Python と部品を、キットの中の `.venv` という部屋にそろえる（初回は数分） |
| `uv run 〇〇` | その部屋の Python で 〇〇 を動かす |
| `uv tool install esptool` | 書き込みの道具 esptool を、どのフォルダからでも使えるように入れる |

> 注意: このとき打つのは、**インターネットからプログラムを取ってきて動かす**命令です。公式の手順と同じ文字か、よく確かめてから打ってください。
> 知らない人から渡された同じような 1 行は、むやみに打たないこと。

🌳 **もう一段** — `uv sync` は、何を見て部品をそろえているの？

> この節も、**今は分からなくても先へ進んでかまいません**。

**まず、たとえで全体を見ます。** 買い物にたとえると、uv は 2 枚の紙を見て、部品をそろえています。

| 買い物 | ファイル | 中身 |
|---|---|---|
| **買い物メモ**（「牛乳」「卵」） | `pyproject.toml` | 欲しい部品の名前と、「この版より新しければよい」という条件 |
| **前回のレシート**（「〇〇牛乳 1 L」と商品まで決まっている） | `uv.lock` | 実際に使う部品の**版をすべて決めた**一覧 |
| **このキット専用の冷蔵庫** | `.venv` フォルダ | そろえた部品の置き場 |

メモだけで買い物に行くと、人によって違う商品を買ってきます。**レシートを渡せば、誰が行っても同じ商品がそろいます**。
`uv.lock` があるので、あなたの PC でも、ゼミの友達の PC でも、作者の PC でも、同じ版の部品がそろいます。
「自分の PC だけ動かない」が起きにくくなるのは、このためです。

**次に、自分の目で確かめます。** 例として、数値計算の部品 **numpy**（ナムパイ）を探します。

**手順 1. 買い物メモを見る** — キットのフォルダの `pyproject.toml` を開き、`numpy` を探します。

```toml
    "numpy>=1.26",
```

`>=1.26` は「版が 1.26 以上なら何でもよい」という条件です。これだけでは、どの版になるかは決まりません。

**手順 2. レシートを見る** — 同じフォルダの `uv.lock` を開き、`name = "numpy"` を探します（とても長いファイルなので、エディタの検索を使います）。

```toml
name = "numpy"
version = "2.2.6"
```

ここで版が **2.2.6** と決まっています。実は numpy は 3 か所あり、ほかに 2.4.6 と 2.5.4 が書かれています。
**使っている Python の版によって、使える numpy の版が違う**ので、Python の版ごとにどれを使うかまで決めてあるのです。

**手順 3. 冷蔵庫を見る** — キットのフォルダに `.venv` というフォルダがあります（`uv sync` をした後にできます）。
そろえた部品はここに入っています。名前が `.` で始まるフォルダは、OS によっては普段は隠れて見えません。

**分かったこと**

- `pyproject.toml` は「欲しいもの」、`uv.lock` は「実際に使う版の確定版」。uv は `uv.lock` のとおりにそろえる
- `.venv` は、消しても `uv sync` でまた作り直せる（冷蔵庫の中身は、レシートがあれば買い直せる）。調子がおかしいときに消して作り直すのは、よくある直し方です

**今は分からなくてよい所:** `uv.lock` のほかの行（`source`・`resolution-markers` など）、版の番号の付け方の決まり。
キットが使っている道具と版の一覧は [docs/dependencies.md](../dependencies.md)、uv を選んだ理由は [ADR 0001](../decisions/0001-target-board-os-and-uv.md) にあります。

## 0-4. キットを手元に置く — git とフォルダ

🌱 **ファーストタッチ**

GitHub は、プログラムを置いておく**共有のクラウドフォルダ**のようなものです。そこからキットを自分の PC に持ってきます。

- **かんたんな方法**: GitHub のページの緑の **`<> Code`** ボタン → **Download ZIP**。ダウンロードした ZIP を**展開**します
  （Windows は右クリック →「すべて展開」。ZIP をダブルクリックして中を見るだけでは展開になりません）
- **git を使う方法**: 変更の履歴ごと持ってくる道具 git を使います。キットが新しくなったときに、差分だけ取り直せます

🌿 **しくみ**

git を使う場合（Windows は先に git を入れます: `winget install --id Git.Git -e`、または https://git-scm.com から）:

```sh
git clone https://github.com/shunan-u-lab/m5stack-csi-kit.git
cd m5stack-csi-kit
uv sync
uv tool install esptool
uv run csikit doctor
```

1 行ずつ打って、それぞれの返事が終わってから次を打ちます。最後の `doctor` は、キットの準備がどこまでできているかを点検し、
足りないものと直し方を表示します。M5Stack Basic をまだつないでいなければ「USB のポートが見えない」と出ますが、それで正常です。

🌳 **もう一段** — `uv run csikit doctor` と打つと、中で何が起きている？

> この節は、**今は分からなくても先へ進んでかまいません**。キットを何度か使ってから戻ってくると、ずっと読みやすくなります。

**まず、たとえで全体を見ます。** 役所の窓口を思い浮かべてください。

1. あなたは**受付**に「点検をお願いします」と言う（ターミナルに `uv run csikit doctor` と打つ）
2. 受付は用件を聞いて、**点検の担当の窓口**に回す
3. 担当の窓口が、決まった順番で点検し（道具 → ファーム → USB → M5Stack Basic → 組）、結果の紙を返す

このキットのプログラムも、同じように **「受付」と「担当の窓口」に分かれています**。

| 役所 | キットのプログラム | ファイル |
|---|---|---|
| 受付 | 打たれた命令（`doctor`・`flash` など）を聞いて、担当に回す | `src/csikit/cli.py` |
| 点検の担当 | 点検を順番に行い、結果をまとめる | `src/csikit/doctor.py` |
| 書き込みの担当 | M5Stack Basic に書き込む | `src/csikit/flash.py` |

**次に、自分の目で確かめます。** プログラムを読む、というより「名前を探す」作業です。
VS Code などのエディタか、メモ帳でファイルを開いてください（書き換えなくて大丈夫です）。

**手順 1. 受付の入口を見つける** — キットのフォルダの `pyproject.toml` を開き、`csikit` という文字を探します。

```toml
[project.scripts]
csikit = "csikit.cli:main"
```

これは「`csikit` と打たれたら、`csikit/cli.py` の中の `main` という名前の処理を動かしてね」という**登録**です。
スマホで、ホーム画面のアイコンを押すとどのアプリが開くかが決まっているのと同じです。

> 言葉: プログラムの中で、名前を付けたひとまとまりの処理を **関数** と言います。`main` は関数の名前です。
> Python では、関数は `def 名前(…):` という行から始まります。

**手順 2. 受付が担当に回す所を見つける** — `src/csikit/cli.py` を開き、`def cmd_doctor` を探します。

```python
def cmd_doctor(_: argparse.Namespace) -> int:
    """点検する."""
    checks = doctor.run()
```

細かい記号は気にせず、**`doctor.run()`** に注目してください。「点検の担当（`doctor.py`）の `run` を動かす」という意味です。
受付は自分では点検せず、担当に回しているだけだと分かります。

**手順 3. 担当の窓口の中を見る** — `src/csikit/doctor.py` を開き、`def run` を探します。

```python
def run(env: Env | None = None) -> list[Check]:
    """全項目を点検する."""
    env = env or Env()
    checks = check_tools(env) + check_images(env)
    port_checks, candidates = check_ports(env)
    checks += port_checks
    board_checks, boards = check_boards(env, candidates)
    return checks + board_checks + check_pair(boards)
```

`check_` で始まる名前を上から拾うと、**tools（道具）→ images（ファーム）→ ports（USB）→ boards（M5Stack Basic）→ pair（組）** の順に並んでいます。
これが、`doctor` の結果の表示の順番そのものです。

**分かったこと**

- 1 行の命令は、「登録（`pyproject.toml`）→ 受付（`cli.py`）→ 担当（`doctor.py`）」とバトンを渡して動いている
- 担当ごとにファイルが分かれているので、**直したい所・知りたい所のファイルだけを開けばよい**
- 担当ごとに、ちゃんと動くかを自動で確かめるプログラム（**テスト**）もあります（`tests/test_doctor.py` など）。`uv run pytest` で全部を動かせます

**今は分からなくてよい所:** `argparse`・`Env | None`・`list[Check]` のような記号、`return` の意味など。
Python を少し学んだ後に読み返すと、1 つずつ意味が分かってきます。気になったら、下の「AI に聞いてみよう」の聞き方で聞いてみてください。

## AI に聞いてみよう

- 「ターミナルの『カレントディレクトリ』を、スマホのファイルアプリでたとえて説明して」
- 「Python の `def run(…):` の行は何を意味するの？ 料理のレシピでたとえて説明して」
- 「`checks = doctor.run()` の 1 行を、プログラミングが初めての人向けに言いかえて」
- 「このエラーが出ました（全部貼る）。最後の行の意味と、まず確かめることを教えて」
- コマンドライン AI なら: 「`uv run csikit doctor` を実行して。実行する前に何をするか教えて。終わったら、受付の `src/csikit/cli.py` から点検の `src/csikit/doctor.py` まで、どの関数がどの順に呼ばれたかを説明して」
- コマンドライン AI なら: 「`pwd` と `ls` を実行して、いまどのフォルダにいて、何が入っているかを、0-2 の言葉で説明して」

**AI に貼らないもの:** 実機の MAC、周りの Wi-Fi の名前（SSID）、パスワード。エラーは全部貼ってよいが、その中にこれらが無いかを先に見る。
