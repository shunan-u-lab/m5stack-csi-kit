# 7. 困ったとき・用語集

[目次](README.md) ・ 前: [6. 解析の入口](06_analysis_intro.md) ・ 次: [8. 安全の仕組み](08_security.md)

困ったら、まず **`uv run csikit doctor`** を動かしてください。`[NG]` の行と、その下の `→` に直し方が出ます。
この章は、その `[NG]` ごとの「何が起きているか」と、`doctor` では分からない困りごとをまとめたものです。

各項目の印:

- **[起きた]** 元の研究で実際に起きたこと
- **[想定]** このキットではまだ起きたことがないが、起こりうると考えていること（キットはまだ実機での確認が済んでいません）

---

## 困ったとき

### 準備（0 章）

| 症状 | 何が起きているか（たとえ） | 直し方 |
|---|---|---|
| `uv` と打つと「見つからない」と出る **[想定]** | uv を入れた直後で、ターミナルがまだ「uv の置き場所」を知らない（新しいアプリのアイコンが、まだホーム画面に出ていない） | ターミナルを閉じて開き直す。それでも駄目なら uv を入れ直す |
| `git` と打つと「見つからない」と出る（Windows）**[想定]** | git が入っていない | `winget install --id Git.Git -e` で入れる。または ZIP でダウンロードする（[0-4](00_pc_basics.md#0-4-キットを手元に置く--git-とフォルダ)） |
| `[NG] esptool: 見つからない` | 書き込みの道具が入っていない | `uv tool install esptool` の後、ターミナルを開き直す |
| `[NG] .bin（tx）: 無い` | M5Stack Basic に入れるファームのファイルが、決まった場所（`out/firmware/`）に無い | Releases から 2 つの `.bin` を取って `out/firmware/` に置く。自分でビルドするなら `uv run python scripts/make_dist.py --build` |
| `uv run csikit …` で「知らない引数」と出る | 命令の綴り・オプションの書き間違い | `uv run csikit --help`、`uv run csikit record --help` で正しい書き方を見る |

### M5Stack Basic をつなぐ（2 章）

本文: [2. M5Stack Basic をつなぐ](02_connect_boards.md)

| 症状 | 何が起きているか（たとえ） | 直し方 |
|---|---|---|
| `[NG] USB のポート: 1 つも見えない` **[想定]** | PC から M5Stack Basic が見えていない。ケーブルが**充電専用**（電気は通るが、データの線が無い）のことが多い。スマホを充電はできるのにパソコンに写真を移せないケーブルと同じ | データ通信のできるケーブルに替える。M5Stack Basic の電源が入っているか（画面が点くか）を見る |
| 同上（Windows・Mac）**[想定]** | USB 変換チップのドライバ（PC が M5Stack Basic と話すための通訳）が入っていない | `doctor` の `→` に出るドライバを入れる（新しい版の M5Stack Basic は CH9102、古い版は CP2104） |
| 同上（WSL・仮想マシン・ChromeOS の Linux）**[想定]** | USB が、Linux の側に渡されていない | ChromeOS は設定の「デベロッパー」→「Linux 開発環境」→「USB デバイスの管理」で M5Stack Basic をオンにする（[付録](chromebook.md)）。WSL は usbipd などで渡す |
| `[NG] 権限: … を読み書きできない`（Linux）**[想定]** | ポートを使う許可が無い（アプリにカメラの許可を出していない状態に似ている） | `sudo usermod -aG dialout $USER` の後、**ログアウトしてログインし直す**（Fedora・Arch は `uucp`） |
| `[NG] M5Stack Basic: …（開けません: busy など）` **[想定]** | 別のアプリがポートを使っている。1 つのポートは同時に 1 つのアプリしか使えない（通話中に別の通話を受けられないのと同じ） | Arduino IDE・シリアルモニタ・別のターミナルの `csikit monitor` などを閉じる |
| `[NG] M5Stack Basic: … WHO に答えない` | このキットのファームが入っていない（買ったときのデモのまま、など）。または 2 台目以降の別の機器 | `uv run csikit flash`（3 章）で書き込む |

### 書き込みと組ませる（3 章）

本文: [3. 書き込みと組ませる](03_flash_and_pair.md)

| 症状 | 何が起きているか（たとえ） | 直し方 |
|---|---|---|
| `flash` で「送信機・受信機のポートを決められません」 | まだ書き込んでいない M5Stack Basic は、自分が送信機か受信機かを答えられない | 1 台ずつつないで `doctor` でポート名を控え、`--tx-port`・`--rx-port` を指定する |
| esptool が途中で失敗する **[想定]** | 書き込み中に接続が切れた。ケーブル・USB ハブの相性、他のアプリがポートを使っている | 直接 PC の USB 口につなぎ、他のアプリを閉じて、もう一度 |
| 「… として答えた（tx のはず）」 | 送信機と受信機のポートを逆に指定した | `--tx-port` と `--rx-port` を入れ替えて、もう一度 `flash` |
| `[NG] 組: 未設定` / 液晶が黄色の `NOT PAIRED` | 2 台が、互いを相手として覚えていない（Bluetooth のペアリング前のイヤホンと同じ） | `uv run csikit flash --pair-only` |
| `[NG] 組: 相手の MAC が合わない` | 別の M5Stack Basic と組んだまま（隣の人のキットと組んでいた、など） | `uv run csikit flash --pair-only` で組ませ直す（鍵も新しくなる） |
| `[NG] 組: ファームが古い` | 組の命令を知らない古いファームが入っている | `uv run csikit flash` で書き直す |
| 書き込み直したら、受信機が時刻を取らなくなった（液晶の時計が `--:--`・SD の記録に開始時刻が入らない） **[想定]** | 書き込みは M5Stack Basic の「設定」の置き場（NVS）も空にする。スマホを初期化すると Wi-Fi のパスワードを入れ直すのと同じ | `uv run python scripts/sd_fetch.py --port <R1 のポート> wifi --ssid <Wi-Fi の名前>` で設定し直す（パスワードは入力を求められ、画面に出ない） |
| 組ませた直後・再起動の後、受信機がしばらく黙る **[起きた]** | 受信機に Wi-Fi を設定してあると、再起動のたびに時刻を取りに行き、その間は黙る（実際に約 16 秒。ファームの待ち時間の上限から見積もると最大約 25 秒） | 待つ（`flash` は最大 40 秒待つ） |

### モニタと記録（4・5 章）

本文: [4. モニタの読み方](04_monitor.md)・[5. 記録とメタデータ](05_record_and_metadata.md)

| 症状 | 何が起きているか（たとえ） | 直し方 |
|---|---|---|
| モニタの題名が `NO SIGNAL` | 受信機に送信機の電波が届いていない | 送信機の電源が入っているか（液晶が緑の `SENDING` か）、2 台が組んでいるか（`doctor`）、離れすぎていないか |
| 受信レートが 100 Hz より大きく下がる・`loss` が多い **[想定]** | 電波が混んでいる（同じチャンネルを近くの Wi-Fi が使っている）、2 台が遠い・間に金属がある | 2 台を近づける。チャンネルを変える（受信機の `CH` 命令。[受信機の README](../../firmware/csi-rx/README.md)） |
| `dropped` が増える **[想定]** | 受信機の中で、PC に送り切れずに捨てた行がある（PC が忙しい・USB が遅い） | 他の重いアプリを閉じる。USB ハブを使わない |
| `bad_crc` が少し出る **[起きた]** | USB の途中で行が壊れた（読み始め・読み終わりの途中の行が多い）。壊れた行は捨てるので記録は正しい | 少しなら気にしなくてよい。増え続けるならケーブルを替える |
| ポートを開いたら、受信機が再起動して約 16 秒黙った **[起きた]** | 普通の開き方では、USB の信号線（DTR/RTS）が受信機のリセットにつながっている | `csikit` は再起動させない開き方をする。他の道具で開くときは注意。`record --reset` は意図してリセットする |
| SD のカードを抜き差ししたら、PC から M5Stack Basic が一瞬消えた **[起きた]** | 抜き差しの電気の揺れで、USB 変換チップが付き直した（本体は動き続けた） | 記録中はカードに触らない。止めてから（ボタン B）抜く |

### エラーの読み方（全般）

- **いちばん下の行から読む。** 最後の行に「何が困ったか」が書いてあることが多い
- `エラー: …` で始まる 1 行は、`csikit` が「想定した失敗」として出しているもので、たいてい直し方まで書いてある
- 何十行も英語が出る（`Traceback` で始まる）ときは、`csikit` が想定していない失敗です。**全部**コピーして、どの命令を打ったかと一緒に、ゼミの人や AI に見せる。
  キットの不具合なら GitHub の issue で知らせてもらえると助かります（返事や修正は約束できません）

### マイコンと接続

| 言葉 | たとえ | 正確には | キットのどこで |
|---|---|---|---|
| マイコン | アプリが 1 つしか入らない小さなコンピュータ | マイクロコントローラ。CPU・メモリ・入出力を 1 つの部品にまとめたもの | M5Stack Basic の中の ESP32 |
| ESP32 | — | Espressif 社のマイコン。Wi-Fi・Bluetooth を内蔵し、CSI を外に出せる | 送信機・受信機 |
| M5Stack Basic | 画面とボタンの付いた小さなスマホ | ESP32 に液晶・3 つのボタン・電池・SD スロット・スピーカーを付けた製品 | 送信機 T1・受信機 R1 |
| ファームウェア | 小さなスマホのたった 1 つのアプリ | マイコンの中で動くプログラム | `firmware/csi-tx`・`firmware/csi-rx` |
| ビルド | — | ソースコードを、マイコンが実行できる形（機械語）に変換すること | PlatformIO（`pio run`） |
| 書き込み（フラッシュ） | アプリの入れ替え（ただし前の中身は消える） | ビルドした結果をマイコンの記憶（フラッシュメモリ）に書くこと | `csikit flash`・esptool |
| `.bin` | アプリのインストールファイル | 書き込み用のファイル。このキットは 1 つにまとめたものを先頭（0x0）に書く | `out/firmware/` |
| シリアル通信 | 文字で話す電話線 | 1 ビットずつ順に送る通信。USB の上で、PC と M5Stack Basic が文字をやりとりする | 命令（`WHO` など）と CSI の行 |
| ポート | 電話番号 | PC から見た、M5Stack Basic とつながる口の名前（Linux は `/dev/ttyACM0`、Windows は `COM3`、Mac は `/dev/cu.…`） | `--port`・`--tx-port` |
| ボーレート | 話す速さ | シリアル通信の速さ [bit/s]。両側で合わないと文字化けする | 送信機 115200、受信機 921600 |
| USB 変換チップ・ドライバ | 通訳・通訳を雇うための登録 | USB とマイコンのシリアルをつなぐ部品（CH9102・CP2104）と、PC がそれを使うためのソフト | `doctor` が見分ける |
| DTR/RTS | M5Stack Basic の「再起動ボタン」につながった線 | シリアルの制御線。M5Stack Basic では本体のリセットにつながっている | `csikit` は開いてから RTS → DTR の順に下げ、再起動させない |
| NVS | 小さなスマホの「設定」の保存場所 | ESP32 のフラッシュの中の、電源を切っても消えない設定の置き場（暗号化はしていない） | 組・Wi-Fi の設定・画面の明るさ。`csikit flash` で書き込むと全部消える（組は入れ直される） |

### 電波と CSI

| 言葉 | たとえ | 正確には | キットのどこで |
|---|---|---|---|
| 電波 | 部屋に響く、見えない音 | 電気と磁気の揺れが空間を伝わる波 | （[1-1](01_what_is_csi.md#1-1-電波は部屋に響く音)） |
| 周波数 | 音の高さ | 1 秒に揺れる回数 [Hz]。Wi-Fi は 2.4 GHz 帯 | ch11 = 2462 MHz |
| 波長 | 波 1 つ分の長さ | λ = c / f。ch11 で約 12.2 cm（計算） | — |
| チャンネル | ラジオの局 | 周波数の区切り。日本の 2.4 GHz 帯は 1〜13 | 既定は 11。`CH` 命令で変えられる |
| 振幅 | 音量・時計の針の長さ | 波の大きさ。CSI では \|H\| | ヒートマップの色 |
| 位相 | 揺れのタイミング・時計の針の角度 | 波の進み遅れ。CSI では ∠H | — |
| 複素数 | アナログ時計の針 | a + jb。長さ（絶対値）と角度（偏角）を 1 つで表す | `io.raw_to_complex` |
| マルチパス | 山びこ・お風呂場の響き | 送信から受信まで、何本もの道（反射）を通った電波が重なって届くこと | 1-4 の図 |
| サブキャリア | イコライザーの棒 1 本 | OFDM で分けた細い周波数の 1 本。間隔 312.5 kHz | 56 本（−28〜−1, 1〜28） |
| OFDM | 合唱（たくさんの声で同時に歌う） | 帯域を多くのサブキャリアに分けて同時に送る方式。Wi-Fi が使う | — |
| CSI | 電波のイコライザー表示 | Channel State Information。サブキャリアごとの通り道の応答 H(f) = Y(f) / X(f) | 記録の `CSI,` の行 |
| RSSI | アンテナ表示（扇形・棒の本数） | 受信した電波の強さ [dBm]。1 パケットに 1 つ | モニタの下の段 |
| dBm | — | 1 mW を基準にした電力の対数の目盛り。10 下がると 1/10 | RSSI の単位 |
| HT-LTF | 決まった合言葉 | 802.11n のパケットの頭にある、中身が決まった信号。CSI を測る基準に使う | 記録の `htltf` |
| ESP-NOW | ESP32 どうしの直通電話 | ルーターを通さずに ESP32 どうしが直接パケットを送る方式 | 送信機のパケット・受信機からの命令 |
| パケット | 1 通の手紙 | 1 回に送るデータのまとまり | 送信機が 10 ms ごとに 1 つ |
| 連番（seq） | 手紙の通し番号 | 送信機がパケットに入れる番号。飛びから欠けが分かる | 記録の `seq` 列 |
| 欠け（loss） | 届かなかった手紙 | 連番の飛びから数えた、届かなかったパケットの割合 | モニタの `loss` |
| dropped | 届いたのに PC へ渡しそびれた手紙 | 受信機の中で、PC に送り切れずに捨てた行の数 | `# stats` の `dropped` |
| CRC | 手紙の封印 | 行の中身から計算する検査用の値。合わない行は壊れているので捨てる | 行の末尾の `*xxxxxxxx` |
| MAC アドレス | 機器の背番号 | ネットワーク機器ごとの識別子（12 桁の 16 進） | 組・`WHO`・記録の `tx` 列 |
| SSID・BSSID | Wi-Fi の名前・その親機の背番号 | アクセスポイントの名前と識別子。場所の手がかりになるので、人に見せるときは伏せる | `beacon_scan.py --mask` |

### キット独自の言葉

| 言葉 | たとえ | 正確には | キットのどこで |
|---|---|---|---|
| 送信機（T1）・受信機（R1） | 合図を出す人・聞く人 | 決まった間隔でパケットを送る M5Stack Basic と、その CSI を測る M5Stack Basic | `firmware/csi-tx`・`csi-rx` |
| 組（ペア） | Bluetooth のペアリング | 2 台が互いの MAC と共通の鍵を覚えている状態。`PAIRSET` で NVS に置く | `csikit flash`（[ADR 0002](../decisions/0002-peer-mac-and-key-in-nvs.md)） |
| 鍵・署名 | 合言葉・本人の印鑑 | 組ごとに乱数で作る 16 バイトの値と、それで計算する HMAC-SHA256。偽の命令を見分ける | [8 章](08_security.md)・[ADR 0005](../decisions/0005-control-auth-and-tx-power.md) |
| `WHO` | 「あなたは誰？」 | M5Stack Basic に役割・MAC・組の状態を答えさせるシリアルの命令 | `doctor`・`flash`・`monitor` |
| メタデータ | 写真の撮影メモ | 記録ごとの条件（配置・人数・区間・品質）を書いた TOML のファイル | `data/meta/`（[ADR 0003](../decisions/0003-recording-metadata-format.md)） |
| ヒートマップ | 色で描いた表 | 横 = 時間、縦 = サブキャリア、色 = 振幅 の図 | `csikit monitor` の上の段 |
| `.csv.zst` | 圧縮した記録 | 記録の CSV を zstd で圧縮したもの。中身は元と同じ | [ADR 0004](../decisions/0004-raw-storage-zstd-parquet.md) |
| 技適 | — | 日本の電波法の技術基準に適合していることの認証。マークの無い機器で電波を出してはいけない | README の「電波法」 |
