# 3. 書き込みと組ませる — `csikit flash`・組（ペア）・鍵

[目次](README.md) ・ 前: [2. M5Stack Basic をつなぐ](02_connect_boards.md) ・ 次: [4. モニタの読み方](04_monitor.md)

この章のゴール: **2 台の M5Stack Basic にこのキットのファームウェアを書き込み、送信機（T1）と受信機（R1）の組にする**こと。
そして、書き込みで何が消えるのか、組とは何を覚えさせることなのかが分かること。

用意するもの: 2 章で `doctor` が 2 つのポートを見つけた状態。書き込み用の `.bin` 2 つ（README の「2. ファームウェアを用意する」で `out/firmware/` に置く）。

---

## 3-1. 書き込み — 「スマホを初期化して、別のアプリだけを入れる」

🌱 **ファーストタッチ**

0 章で、M5Stack は「アプリが 1 つしか入らない小さなスマホ」だと説明しました。
**書き込み**は、そのスマホを初期化して、このキットのアプリ（送信機用か受信機用）を入れることです。
初期化なので、**買ったときに入っていたデモや、前に入れたプログラムは消えます**。

🌿 **しくみ**

- 送信機にする M5Stack Basic には送信機用の `.bin`、受信機にする M5Stack Basic には受信機用の `.bin` を書きます
- 書き込むと、M5Stack Basic の中の**設定の置き場（NVS）も空になります**。前に入れた組（3-2）、受信機の Wi-Fi の設定、画面の明るさが消えます。
  組は `flash` が入れ直しますが、Wi-Fi の設定は入れ直しません（時刻を使う人は README の「4. 書き込んで組ませる」の手順で）
- **元の中身を残したいとき**（研究室から借りた M5Stack Basic・別の研究で使っている M5Stack Basic）は、先に吸い出します。1 台あたり数分かかります

```sh
uv run python scripts/backup_flash.py --port <ポート> --label <名前>
```

吸い出したファイル（`data/firmware-backup/`）には、その M5Stack Basic の鍵や Wi-Fi のパスワードが入っています。人に渡さないでください（8 章）。

🌳 **もう一段** — 書き込みのとき、実際には何が起きているの？

> この節は、**今は分からなくても先へ進んでかまいません**。

**まず、たとえで全体を見ます。** ESP32 の中には、電源を切っても消えない**ノート（フラッシュメモリ、4 MB 以上）**があります。
書き込みは、このノートの**先頭（0 番地）から**、`.bin` の中身を写していく作業です。写し終わったら、写したものと `.bin` が同じかを**照合**します。

`.bin` の中には、起動の手順書（ブートローダ）・ノートの目次（パーティション表）・アプリ本体が、決まった位置に並べてまとめてあります。
目次の後ろの「設定の置き場（NVS）」の位置は空白（0xFF）でまとめてあるので、書き込むと NVS も空白で上書きされます。これが「設定が消える」理由です。

**次に、自分の目で確かめます。** `csikit flash` が実際に動かす命令を、書き込まずに表示します（実機は要りません）。

```sh
uv run python -c "from pathlib import Path; from csikit import flash; print(' '.join(flash.write_command('esptool', '/dev/ttyACM0', Path('out/firmware/csi-tx-m5stack-basic.bin'))))"
```

次のように出れば正解です。

```
esptool --chip esp32 --port /dev/ttyACM0 --baud 460800 write-flash 0x0 out/firmware/csi-tx-m5stack-basic.bin
```

「ESP32 用に、このポートへ、460800 bit/s で、0 番地（`0x0`）から、この `.bin` を書く」という意味です。
Windows では、ファイルの場所の区切りが `\` で表示されます（`out\firmware\…`）。意味は同じです。

**分かったこと**

- 書き込みは esptool（Espressif が作った道具）に任せている。`csikit` は命令を組み立てて呼んでいるだけ（`src/csikit/flash.py`）
- 書き込みのとき、esptool は 2 章の DTR・RTS の合図で、ESP32 を**わざと**「書き込み待ち」で再起動させている

**今は分からなくてよい所:** ブートローダ・パーティション表の中身と位置（`scripts/make_dist.py` の説明にある）。書き込みの速さの決め方。

## 3-2. 組（ペア）— 「2 台だけの合言葉を覚えさせる」

🌱 **ファーストタッチ**

ワイヤレスイヤホンは、一度スマホとペアリングすると、そのスマホとだけつながります（8 章でも使ったたとえです）。
送信機と受信機も、書き込みの後に**組**にします。組になると、2 台は**お互いの名前（MAC）と、2 台だけが知っている鍵**を覚えます。

🌿 **しくみ**

- `csikit flash` は、書き込みが終わると、自動で組ませます。鍵は PC がその場で乱数から作り、**画面には出しません**
- 組になった受信機は、組んだ送信機の電波だけを CSI として使います。隣の席に別のキットがあっても混ざりません
- 受信機は、組んだ送信機に、無線で「チャンネルを変えて」「出力を下げて」と命令できます。鍵で署名するので、他人は同じ命令を送れません（8 章）
- 組が無い M5Stack Basic は、液晶に黄色の `NOT PAIRED` が出て、無線の命令を受け付けません

🌳 **もう一段** — 組ませるとき、PC は M5Stack Basic に何を送っているの？

> この節は、**今は分からなくても先へ進んでかまいません**。

**まず、たとえで全体を見ます。** 2 台にそれぞれ、「あなたの相手はこの人で、合言葉はこれ」というメモを渡します。
メモを受け取った M5Stack Basic は、メモを NVS にしまって再起動し、次からはそのメモに従って動きます。

**次に、自分の目で確かめます。** そのメモ（`PAIRSET` という命令）の形を、**練習用のダミーの値**で作ってみます（実機は要りません）。

```sh
uv run python -c "from csikit import pairing; print(pairing.pairset_command('020000000002', '0' * 32))"
```

`PAIRSET 020000000002 00000000000000000000000000000000` と出れば正解です。
前半が相手の MAC、後半が鍵（16 バイトを 16 進数の 32 文字で書いたもの）です。**本物の鍵でこの行を表示したり、人に見せたりしてはいけません**。

**分かったこと**

- 組ませる流れは、送信機に「相手は受信機、鍵はこれ」、受信機に「相手は送信機、鍵は同じもの」を送り、両方が再起動した後に `WHO` で `paired=1` と相手の MAC を確かめる（`src/csikit/pairing.py` の `pair`）
- 古いファームは知らない命令をそのまま返してくるので、`paired=` を返さない M5Stack Basic には `PAIRSET` を送らない（鍵が画面に漏れるのを防ぐ）

**今は分からなくてよい所:** NVS の中の並び（`firmware/shared/CsiPair/src/CsiPair.h`）。再起動を待つ時間の決め方。

## 3-3. やってみる — `csikit flash`

🌱 **ファーストタッチ**

ここからが本番です。**初めての 2 台は、どちらを送信機にするかを自分で決めます**（まだ何も入っていないので、M5Stack Basic は自分が何者か答えられません）。
マスキングテープに `T1`（送信機）・`R1`（受信機）と書いて貼っておくと、後で迷いません。

🌿 **しくみ** — 手順

1. **1 台だけ** USB でつなぎ、`uv run csikit doctor` でポート名を控えます（例: `/dev/ttyACM0`。Windows は `COM3` など）。これを T1 にします
2. もう 1 台をつなぎ、`doctor` で増えたほうのポート名を控えます。これを R1 にします
3. 2 台ともつないだまま、書き込みます

```sh
uv run csikit flash --tx-port <T1 にするポート> --rx-port <R1 にするポート>
```

4. 「書き込みますか [y/N]」と聞かれたら、ポートの組み合わせを見直してから `y` と Enter
5. esptool の表示（`Writing at …` の進み具合と `Hash of data verified.`）が 2 台分流れ、続いて組ませます。受信機は再起動に最大 40 秒ほどかかります

うまくいったときの最後の表示の例（MAC はダミー）:

```
組ませています（両方が再起動します。受信機は最大 40 秒ほどかかります）
送信機（T1）: /dev/ttyACM0  mac=02:00:00:00:00:01  fw=1028-a74b527
受信機（R1）: /dev/ttyACM1  mac=02:00:00:00:00:02  fw=1028-a74b527
組ませました。次は uv run csikit monitor
```

液晶は、送信機が緑の `SENDING`、受信機が緑の `RX from T1` になります。画面の上の帯の左端の文字が機器番号（`T1`・`R1`）です。
最後に `uv run csikit doctor` で「問題はありません」と出れば、この章は終わりです。

**2 回目からは**、ポートを指定しなくてもかまいません。書き込んだ M5Stack Basic は `WHO` に答えるので、`csikit` が見分けます。

| したいこと | 命令 |
|---|---|
| ファームを新しい版に書き直す | `uv run csikit flash` |
| 書き込まずに組ませ直す（鍵も新しくなる） | `uv run csikit flash --pair-only` |
| M5Stack Basic を人に渡す前に組を消す | `uv run csikit unpair`（2 台ともつないで。8 章） |

🌳 **もう一段** — 組ませ直しと、鍵が合わないときに起きること

> この節は、**今は分からなくても先へ進んでかまいません**。

**まず、たとえで全体を見ます。** 合言葉を変えたのに、片方にだけ新しい合言葉を伝えると、2 人は話が通じなくなります。
`--pair-only` は、2 台に**同時に**新しい合言葉を渡すので、通じなくなることはありません。

**次に、自分の目で確かめます。** 2026-10-28 に実機で、わざと送信機にだけ別の鍵を入れて試しました（[試験の記録](../test-log/2026-10-28-kit-firmware-flash-and-pair.md)）。

| 試したこと | 結果 |
|---|---|
| 受信機に「チャンネルを 6 に」（`CH 6`） | 送信機が署名を確かめられず、`reason=tx_no_ack`（了解なし）で失敗。2 台とも元のチャンネルのまま |
| 受信機の組を消した（`PAIRCLEAR`）後に `doctor` | `[NG] 組: 未設定（送信機 paired=1・受信機 paired=0）` → `flash --pair-only` を案内 |
| `uv run csikit flash --pair-only` | 元どおり。`doctor` は「問題はありません」 |

**分かったこと**

- 鍵が合わないと、命令は「安全側」に失敗する（勝手にチャンネルが変わったりしない）。困ったら `--pair-only` で組ませ直せばよい

**今は分からなくてよい所:** 了解（ack）を何回待つか。受信機と送信機が同時にチャンネルを変える手順（4 章で使う `CH` 命令の中身）。

## 確かめよう

1. 書き込みで消えるものを 3 つ挙げられる？　そのうち `flash` が自動で入れ直すものは？
2. 初めての 2 台で、`--tx-port`・`--rx-port` を指定しなければならないのはなぜ？
3. 研究室から借りた M5Stack に書き込む前に、何をする？
4. 隣の席の人と同じ部屋で測っても、CSI が混ざらないのはなぜ？

<details>
<summary>答え</summary>

1. 元のプログラム（デモなど）・組（相手の MAC と鍵）・受信機の Wi-Fi の設定（ほかに画面の明るさ）。`flash` が入れ直すのは組だけ
2. まだこのキットのファームが入っていないので、M5Stack Basic が `WHO` に答えられず、どちらを送信機にするかを `csikit` が決められないから
3. `scripts/backup_flash.py` で元の中身を吸い出す（返すときに書き戻せるように）
4. 受信機は、組んだ送信機（覚えている MAC）の電波だけを CSI として使うから

</details>
