# 2. M5Stack Basic をつなぐ — USB・ポート・`csikit doctor` の読み方

[目次](README.md) ・ 前: [1. CSI とは](01_what_is_csi.md) ・ 次: [3. 書き込みと組ませる](03_flash_and_pair.md)

この章のゴール: **M5Stack Basic を 2 台 PC につなぎ、`uv run csikit doctor` の表示を 1 行ずつ読める**こと。
そして、PC が「どちらが送信機で、どちらが受信機か」をどうやって見分けているかが分かること。

用意するもの: M5Stack Basic 2 台、**データ通信のできる** USB ケーブル 2 本、0 章で `uv sync` まで済ませた PC。
Chromebook の人は、先に [付録](chromebook.md) の手順 5（USB を Linux に渡す）まで進めてください。

---

## 2-1. USB ケーブルは「充電だけ」と「通信もできる」がある

🌱 **ファーストタッチ**

スマホを PC につないで写真を取り込もうとしたら、充電は始まるのに PC に何も出てこなかった、という経験はありませんか。
USB ケーブルには、**電気だけを通すもの（充電専用）**と、**電気とデータの両方を通すもの**があります。見た目ではほとんど区別できません。

M5Stack と PC が話すには、**データも通るケーブル**が要ります。

🌿 **しくみ**

- 充電専用のケーブルでつなぐと、M5Stack の画面は点く（電気は来る）のに、PC からは何も見えません
- うまくいかないときは、まずケーブルを替えます。スマホの写真を取り込めたケーブルなら、データも通ります
- USB ハブを通すと不安定になることがあります。最初は PC の USB の口に直接つなぎます

🌳 **もう一段** — PC は、つながった機器をどうやって見分けているの？

> この節は、**今は分からなくても先へ進んでかまいません**。

**まず、たとえで全体を見ます。** USB の機器は、つながった瞬間に PC へ**名刺**を渡します。名刺には「どこの会社の（VID）」「何という製品か（PID）」が番号で書いてあります。
M5Stack Basic の中には、USB とマイコン（ESP32）の間を取り持つ小さなチップ（**USB 変換チップ**）があり、名刺を出すのはこのチップです。

**次に、自分の目で確かめます。** 2 台をつないだまま、名刺を一覧にします（実機が要ります）。

```sh
uv run python -m serial.tools.list_ports -v
```

M5Stack Basic なら `VID:PID=1A86:55D4`（CH9102。新しい版）か `VID:PID=10C4:EA60`（CP2104。古い版）が出ます。
`SER=` の後ろは、その機器だけの番号（シリアル番号）です。人に見せる画面では伏せます。

**分かったこと**

- `csikit doctor` は、この名刺の番号で「M5Stack Basic の USB 変換チップだ」と見分けている（`src/csikit/ports.py` の `KNOWN_CHIPS`）
- 名刺は USB 変換チップのものなので、**ESP32 の中のプログラムが何であっても同じ**。中身（送信機か受信機か）は、次の 2-3 で別の方法で見分ける

**今は分からなくてよい所:** USB の規格の細かい話。VID・PID の割り当ての仕組み。

## 2-2. ポート — 「PC 側の差し込み口の名前」

🌱 **ファーストタッチ**

Bluetooth のイヤホンをつなぐと、スマホの設定に「〇〇のイヤホン」という名前が出ます。
M5Stack を USB でつなぐと、PC の中に、その M5Stack Basic と話すための**窓口（シリアルポート）**ができ、名前が付きます。

| OS | ポートの名前の例 |
|---|---|
| Linux・Chromebook | `/dev/ttyACM0`・`/dev/ttyACM1`（古い版は `/dev/ttyUSB0`） |
| Windows | `COM3`・`COM4` など |
| Mac | `/dev/cu.usbserial-…`・`/dev/cu.wchusbserial…` など |

🌿 **しくみ**

- 1 台つなぐと 1 つ、2 台つなぐと 2 つのポートができます。**どちらがどちらかは、つないだ順や口で変わります**
- 1 つのポートは、**同時に 1 つのアプリしか使えません**。別のアプリ（Arduino IDE のシリアルモニタなど）が開いていると、`csikit` は使えません
- Windows・Mac では、USB 変換チップの**ドライバ**（チップと話すための翻訳係）を入れないと、ポートができないことがあります。`doctor` が入手先を教えます
- Linux では、ポートを使える集団（`dialout`）に入っている必要があります（README の「1. 道具を入れる」）

🌳 **もう一段** — 「シリアル」の速さ

> この節は、**今は分からなくても先へ進んでかまいません**。

**まず、たとえで全体を見ます。** 2 人が 1 本の糸電話で話すとき、話す速さをそろえないと聞き取れません。
シリアル通信も、PC と M5Stack Basic が**同じ速さ（ボーレート、単位は bit/s）**で話す決まりです。

このキットでは、送信機は **115200 bit/s**、受信機は **921600 bit/s** で話します。受信機は CSI をたくさん送るので速くしています。

**次に、自分の目で確かめます。** 受信機が 1 秒に送るデータの量を見積もります。CSI の 1 行はおよそ 330 文字（2026-10-28 の記録の平均）、1 秒に約 100 行です。

```sh
uv run python -c "print(330 * 100 * 10, 'bit/s 必要', 921600, 'bit/s ある')"
```

1 文字を送るのに約 10 bit 使うので、必要なのは約 33 万 bit/s です。115200 では足りず、921600 なら余裕があります。

**分かったこと**

- 受信機の速さは、CSI を取りこぼさずに PC へ送るために決めてある（`src/csikit/ports.py` の `TX_BAUD`・`RX_BAUD`）

**今は分からなくてよい所:** 1 文字が 10 bit になる理由（スタートビット・ストップビット）。行の正確な長さ。

## 2-3. `csikit doctor` — 健康診断の結果を読む

🌱 **ファーストタッチ**

健康診断の結果票には、項目ごとに「異常なし」「要再検査」と書いてあり、「要再検査」には何をすればよいかが添えてあります。
`uv run csikit doctor` は、キットの健康診断です。道具・ファイル・USB・M5Stack Basic・組を順に調べ、問題があれば直し方を出します。

```sh
uv run csikit doctor
```

🌿 **しくみ** — 印の意味

| 印 | 意味 |
|---|---|
| `[OK]` | 問題なし |
| `[--]` | お知らせ（問題ではない。見つかったものを並べているだけ） |
| `[NG]` | 問題あり。次の行の `→` に直し方 |

**買ったばかりの M5Stack をつないだとき**（まだこのキットのファームが入っていない）の表示の例:

```
[OK] Python: 3.14
[OK] esptool: /home/you/.local/bin/esptool
[--] PlatformIO: 無し（ファームを自分でビルドする人だけ要る: …）
[OK] .bin（tx）: …/m5stack-csi-kit/out/firmware/csi-tx-m5stack-basic.bin
[OK] .bin（rx）: …/m5stack-csi-kit/out/firmware/csi-rx-m5stack-basic.bin
[--] USB のポート: /dev/ttyACM0（CH9102・USB Single Serial）
[--] USB のポート: /dev/ttyACM1（CH9102・USB Single Serial）
[NG] M5Stack Basic: /dev/ttyACM0: WHO に答えない
       → このキットのファームが入っていない。uv run csikit flash で書き込む
[NG] M5Stack Basic: /dev/ttyACM1: WHO に答えない
       → このキットのファームが入っていない。uv run csikit flash で書き込む
[NG] 送信機（T1）: 見つからない
       → 2 台とも USB でつなぐ（書き込み前なら uv run csikit flash）
[NG] 受信機（R1）: 見つからない
       → 2 台とも USB でつなぐ（書き込み前なら uv run csikit flash）

4 件の問題があります（→ の手順で直してから、もう一度 csikit doctor）
```

この段階の `[NG]` は**正常**です。次の 3 章で書き込めば消えます。

**書き込んで組ませた後**の表示の例（MAC はダミーに置き換えています）:

```
[--] USB のポート: /dev/ttyACM0（CH9102・USB Single Serial）
[--] USB のポート: /dev/ttyACM1（CH9102・USB Single Serial）
[OK] 送信機（T1）: /dev/ttyACM0  mac=02:00:00:00:00:01  fw=1028-a74b527
[OK] 受信機（R1）: /dev/ttyACM1  mac=02:00:00:00:00:02  fw=1028-a74b527
[OK] 組: 送信機と受信機が互いを相手にしている

問題はありません。次は uv run csikit monitor
```

読み方:

- **上から順に、土台から**調べています（道具 → ファイル → USB → M5Stack Basic → 組）。上に `[NG]` があると、下の項目は正しく調べられないので、**いちばん上の `[NG]` から**直します
- `mac=` は M5Stack Basic ごとに決まった番号です。人に見せる画面では伏せます（1-6・8 章）
- `fw=` はファームウェアの版です（作った月日とコードの版）

`[NG]` の一覧と直し方は [7 章の「困ったとき」](07_troubleshooting_glossary.md#m5stack-basic-をつなぐ2-章) にあります。

🌳 **もう一段** — どうやって送信機と受信機を見分けているの？

> この節は、**今は分からなくても先へ進んでかまいません**。

**まず、たとえで全体を見ます。** 同じ形の名札を付けた 2 人がいたら、「あなたは誰？」と聞けば分かります。
2-1 の名刺（USB 変換チップの番号）は 2 台とも同じなので、`doctor` は各ポートに **`WHO`（あなたは誰？）**という命令を送り、返事で見分けます。
返事には、役割（`role=tx` か `role=rx`）・自分の MAC・組んでいる相手・組の有無（`paired=`）・版が入っています。

**次に、自分の目で確かめます。** 受信機の返事の例（MAC はダミー）を、キットのコードに読ませます（実機は要りません）。

```sh
uv run python -c "from csikit import ports; b = ports.parse_who('# who role=rx mac=020000000002 channel=11 format=3 tx_mac=020000000001 relay=1 pico=0 auth=on tx_power_dbm=19.50 fw=1028-a74b527 paired=1'); print(b.role, b.mac, b.peer_mac, b.paired)"
```

`rx 020000000002 020000000001 True` と出れば正解です。役割・自分の MAC・相手の MAC・組の有無が取り出せました。

**分かったこと**

- `doctor` は、ポートを 2 つの速さ（921600 と 115200）で順に開き、`WHO` に答えた速さと返事で、送信機か受信機かを決めている（`src/csikit/ports.py` の `identify`）
- 買ったばかりの M5Stack Basic は `WHO` を知らないので答えない。だから「このキットのファームが入っていない」と分かる

**今は分からなくてよい所:** 返事の全部の項目。正規表現（返事から値を取り出す書き方）。

## 2-4. ポートを開くと M5Stack Basic が再起動する？ — 実際に起きた不具合

🌱 **ファーストタッチ**

スマホの充電ケーブルを抜き差ししただけで、スマホが再起動したら困ります。
ところが M5Stack Basic は、**PC がポートを開くやり方によっては、再起動してしまいます**。

🌿 **しくみ**

- USB 変換チップには、データの線のほかに **DTR・RTS** という 2 本の合図の線があります。M5Stack Basic では、この線が ESP32 の**リセット（再起動）**につながっています
- 書き込みのときは、この合図でわざと ESP32 を書き込み待ちにします（3 章）。便利な仕組みですが、**普通に開いたときにも合図が出てしまう**ことがあります
- 受信機が再起動すると、時刻を取りに行く間（設定していれば十数秒）、CSI が止まります
- `csikit` は、再起動させない順番で合図の線を扱います。**別のアプリ（シリアルモニタなど）で開くと再起動することがあります**

🌳 **もう一段** — 線を下げる「順番」で、なぜ結果が変わるの？

> この節は、**今は分からなくても先へ進んでかまいません**。

**まず、たとえで全体を見ます。** 2 つのスイッチ A・B があり、「A だけが切れて B が入っている」瞬間があると警報が鳴る、という装置を考えます。
両方とも入っている状態から両方を切りたいとき、**A を先に切ると、一瞬だけ警報の条件になります**。B を先に切れば鳴りません。

M5Stack Basic のリセットの回路は、この「警報」に近い作りです。A が DTR、B が RTS にあたります。

**次に、自分の目で確かめます。** このキットでは、2026-10-28 に実機で次のことが起きました（[試験の記録](../test-log/2026-10-28-open-without-reset-doctor-monitor-record.md)）。

| 開き方 | 再起動した回数 |
|---|---|
| 開く**前に** DTR・RTS を下げる設定にしておく（それまでのキット） | 3 回中 3 回 |
| 普通に開いてから **RTS → DTR** の順に下げる（直した後） | 3 回中 0 回 |

Linux では、ポートを開いた瞬間に 2 本とも上がり、その後に 1 本ずつ下がります。DTR を先に下げると「DTR だけ下がった」瞬間ができ、再起動していました。
直した後のコードは `src/csikit/ports.py` の `open_no_reset` で、順番は `tests/test_ports.py` のテストで固定しています。

**分かったこと**

- 「開く前に線を下げておけば安全」という思い込みが、実機では逆だった。**実機で確かめる**ことと、確かめた結果を**テストで固定する**ことが大事

**今は分からなくてよい所:** リセットの回路図（トランジスタ 2 つの組み合わせ）。OS ごとの違い（Windows・Mac では確かめていない）。

## 確かめよう

1. 充電専用のケーブルでつなぐと、M5Stack の画面と PC の見え方はそれぞれどうなる？
2. `doctor` に `[NG]` が 3 つ出た。どれから直す？
3. 2 台とも同じ `VID:PID=1A86:55D4` なのに、`doctor` が送信機と受信機を区別できるのはなぜ？
4. 買ったばかりの M5Stack で「WHO に答えない」と出た。故障？

<details>
<summary>答え</summary>

1. 画面は点く（電気は来る）が、PC からはポートが見えない
2. いちばん上の `[NG]` から（下の項目は上の項目が正しい前提で調べている）
3. `VID:PID` は USB 変換チップの名刺で、2 台とも同じ。`doctor` は各ポートに `WHO` を送り、ESP32 の中のファームの返事（`role=tx`・`role=rx`）で区別している
4. 故障ではない。このキットのファームがまだ入っていないので、`WHO` を知らない。3 章で書き込む

</details>

## AI に聞いてみよう

- 「USB のシリアル通信のボーレートとは何か、糸電話のたとえで説明して。115200 と 921600 の違いも」
- 「ESP32 の自動リセット回路（DTR と RTS）の仕組みを、図を描くように言葉で説明して」
- コマンドライン AI なら: 「`src/csikit/ports.py` の `identify` を開いて、`WHO` で送信機と受信機を見分ける流れを、関数の名前を挙げながら説明して」

**AI に貼らないもの:** 実機の MAC、`SER=` のシリアル番号、周りの Wi-Fi の名前（SSID）。
