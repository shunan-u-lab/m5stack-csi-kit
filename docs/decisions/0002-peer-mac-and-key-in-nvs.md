# 0002. 相手の MAC と制御の鍵は、書き込み後にシリアルで NVS に設定する

- ステータス: **採用**（2026-10-27）
- 対象: firmware/csi-tx・csi-rx・shared、`csikit flash`

## 背景

元のファームでは、相手の MAC（送信機は受信機の、受信機は送信機の）を `platformio.ini` の `build_flags`
（`-D CSI_RX_MAC=…`・`-D CSI_TX_MAC=…`）でビルド時に埋め込み、制御パケットの署名の鍵も
環境変数 `CSI_CTRL_KEY` からビルド時に埋め込んでいた（`-D CSI_CTRL_KEY_HEX=…`）。

キットでは利用者ごとに基板の MAC が違い、鍵も利用者ごとに別にすべきである。選択肢:

1. 今のまま。利用者が `platformio.ini` に MAC を書き、環境変数に鍵を置いて自分でビルドする
2. ブロードキャストで相手を決めず、最初に聞こえた相手と組む（自動で組む）
3. 1 種類のビルド済み `.bin` を配り、書き込み後にシリアルの命令で相手の MAC と鍵を NVS に置く

## 決定

**3 を採る。** 1 種類の `.bin`（送信機用・受信機用）を配り、`csikit flash` が書き込みの後に

1. 両方の基板に `WHO` を送って、それぞれの MAC と役割（tx/rx）を読む
2. 鍵を PC 側で乱数から作る（16 バイト）
3. 送信機に「受信機の MAC と鍵」、受信機に「送信機の MAC と鍵」をシリアルの命令で送り、NVS に置かせる
4. 再起動して `WHO` で設定が効いたこと（相手の MAC・`auth=on`）を確かめる

- NVS が空（相手・鍵が未設定）のときは、無線の命令を受け付けず、液晶とシリアルに「未設定」と出す（失敗時は安全側）
- 鍵の値はシリアルの応答・液晶・ログに出さない（設定済みかどうかだけ出す）。受信機の Wi-Fi のパスワードと同じ扱い
- 消す命令を用意する（機材を返す・人に渡す前に使う）
- 元の研究で使っているファームは変えない（キット側だけの変更）

## 根拠

- 1 は手順が長く、ビルドの環境（Apple Silicon の問題・Windows の `python3`）を全員が踏む。ADR 0001 の「ビルド済み `.bin` を標準にする」と両立しない
- 2 は、同じ部屋で複数の組が動く研究室（隣の学生のキット）で、他人の送信機と組んでしまう。CSI は「どの送信機からの電波か」が記録の前提なので、相手は明示して固定する
- 3 は、受信機の Wi-Fi の名前とパスワードを NVS に置く既存の仕組み（`sd_fetch.py wifi`）と同じ形で、実装と説明を共有できる
- 鍵を利用者ごとの乱数にすれば、配った `.bin` に鍵が入らない。同じ部屋の他の組からの命令も署名で弾ける
