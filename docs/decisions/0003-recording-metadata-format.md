# 0003. 記録ごとに条件を TOML のメタデータとして残す

- ステータス: **採用**（2026-10-27。元の研究リポジトリで 2026-09-23 に決めた判断を引き継ぐ）
- 対象: `src/csikit/meta.py`・`scripts/capture_csi.py`・`scripts/check_meta.py`・`scripts/fill_meta.py`・`examples/meta/`

## 背景

CSI の変化の現れ方は、部屋・配置・人の位置で変わる。元の研究では、CSI の記録そのものより
「そのとき何が起きていたか」の記録が足りずに結論を出せない場面が続いた。

- 静止の記録の途中にある振幅の山が、実際の動きかラベルの誤りか確定できない（記録者の動きの記録がない）
- 歩行の鋭い山が、送受の見通し線を横切った時刻と対応するか確かめられない（時刻の記録がない）
- 午後に RSSI が約 11 dB 低く欠番率が 2 倍以上になったが、午前と配置がどう違うか比べられない

記録どうしを比べるには、条件を後から読める形で残す必要がある。形式の選択肢:

| 候補 | 判断 |
|---|---|
| **TOML** | **採用。** 手で書きやすく、コメントが書ける。Python 3.11+ は標準の `tomllib`（3.10 は `tomli`） |
| YAML | 手書きしやすいが、依存が増え、暗黙の型変換（`no` → false 等）で事故が起きやすい |
| JSON | 標準ライブラリで読めるが、コメントが書けず、手で書くと末尾のカンマ等で壊れやすい |
| 記録の CSV の `#` 行 | 記録と一体で失われにくいが、記録後に追記・訂正しづらい。**印（`# mark`）は CSV に残し、条件はメタデータに書く**と分担する |

## 決定

### 置き場所と名前

- 記録 1 本につきメタデータ 1 ファイル。`data/meta/<記録名>.toml`（記録名 = 記録のファイル名から `.csv`・`.csv.zst` を除いたもの）
  - 例: `data/raw/20260101-120000-static.csv` → `data/meta/20260101-120000-static.toml`
- 雛形は `examples/meta/TEMPLATE.toml`、記入例は `examples/meta/`
- 配置の写真は `data/raw/<記録名>-<番号>.jpg` に置き、メタデータからファイル名で参照する
- このキットのリポジトリでは `data/` を git に入れない。自分の研究のリポジトリでは、**メタデータは小さく取り直せないので git に入れる**ことを勧める

### 項目（schema = 1）

必須は **[必須]**。分からない値は項目ごと省かず `"unknown"` と書く（書き忘れと区別するため）。未記入は `"TODO"`。

| 表 | 項目 | 内容 |
|---|---|---|
| （先頭） | `schema` [必須] | 書式の版。今は `1` |
| | `recording` [必須] | 記録名（ファイル名と一致させる） |
| | `experiment` [必須] | 実験の呼び名（例: `exp01`）。試験記録は `test` |
| | `label` [必須] | 記録時のラベル（ファイル名の末尾と同じ） |
| | `purpose` | この記録で何を確かめるか（1 文） |
| `[time]` | `start` [必須] / `duration_sec` [必須] | 開始時刻（ISO 8601・タイムゾーン付き）・記録時間 [sec] |
| `[[devices]]` | `role` / `name` / `board` / `mac` / `firmware` / `firmware_rev` | 送信機・受信機それぞれ（`mac` と `firmware` は必須） |
| `[radio]` | `channel` / `bandwidth` / `mcs` / `tx_rate_hz` [必須] | 無線の条件 |
| `[placement]` | `room` [必須] / `tx_rx_distance_m` [必須] / `line_of_sight` / `photos` | 部屋の呼び名（`room-A` 等。**住所・実名は書かない**）・送受の距離 [m]・見通し・写真 |
| `[[placement.nodes]]` | `name` / `height_m` / `antenna` / `surroundings` | 各基板の高さ [m]・向き・周囲（金属・PC・ケーブル） |
| `[environment]` | `people_in_room` [必須] / `other_activity` | 部屋にいた人数・被験者以外の動き（「なし」も明記） |
| `[[subjects]]` | `id` / `role` | 被験者の ID（`P1` 等。**実名は書かない**）と役割 |
| `[[segments]]` | `start_sec` / `end_sec` / `activity` / `where` [必須] | **予定した**区間。実際の切り替え時刻は CSV の `# mark` 行が正 |
| `[[events]]` | `t_sec` / `note` / `confirmed` | **予定外**の出来事。確かでなければ `confirmed = false` |
| `[quality]` | `rate_hz` / `missing_seq` / `bad_crc` / `rssi_mean_dbm` | 記録の品質（記録ツールの集計から写す） |
| `[status]` | `usable` [必須] / `issues` | 解析に使えるか・使ううえでの注意 |

### 書く人・書く時

- **記録の前**に条件（配置・予定の区間・在室者）を決めておく。前回と同じ配置なら `--meta-base` で写す
- **記録の後**、記録ツールが書いた下書きの `TODO` をすぐに埋める（記憶が新しいうちに。`scripts/fill_meta.py`）
- `scripts/check_meta.py` で、欠け・形の問題・未記入がないことを確かめる

### 強制の仕組み

| 仕組み | 見るもの |
|---|---|
| 記録ツール | 記録が終わると下書きを書く（上書きしない）。時刻・MAC・チャンネル・MCS・品質・印（区間と出来事）は自動で埋める |
| `scripts/check_meta.py` | 全記録にメタデータがあるか・形の問題・未記入。問題があれば終了コード 1 |
| pytest（`tests/test_meta.py`） | `examples/meta/` が全件読め、形の問題がなく、ファイル名と一致すること |

## 根拠

- 手書きだけでは書き忘れ・食い違いが起きる。自動で埋められる項目は記録ツールが埋め、欠けと未記入は点検で見つける
- `"unknown"` と `"TODO"` を分けると、「分からない」と「まだ書いていない」を区別でき、点検が未記入だけを数えられる
- 残る穴: 点検は手で走らせる必要がある。記録は git の外なので、git の仕組みでは「記録があるのにメタデータがない」を検出できない
