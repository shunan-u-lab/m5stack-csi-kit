# 0008. 生成 AI と一緒にも、一人でも、動かしながら仕組みを学べる形にし、作者固有の設定を外す

- ステータス: **採用**（2026-10-28。方向のみ。中身は段階的に作り、要所で利用者に確認する）
- 対象: `AGENTS.md`・`CLAUDE.md`・`GEMINI.md`・`docs/tutorial/`・`.githooks/`・`docs/structure.md`・`docs/requirements.md`・`tools.toml`
- 関連: ADR 0007（初学者向けの 3 段のチュートリアル）

## 背景

利用者（作者）からの依頼（2026-10-28）:

1. 生成 AI を活用しながら進め、**動かしながら、コンピュータの仕組みを理解できる**仕組みにする
2. **自分でチュートリアルを見ながら**（AI なしでも）使えるようにする
3. 作者固有の環境設定を整理し、**他の環境で AI が迷わない**ようにする

今の状態:

- 開発は作者の Claude Code で進めてきた。`AGENTS.md` を正とし、`CLAUDE.md`・`GEMINI.md` は `@AGENTS.md` だけ（Codex は `AGENTS.md` を直接読む）
- `AGENTS.md` には作者の PC にしか無いもの（作者用の規約のファイル・個人情報を止めるフック・運用の記録のリポジトリ・
  リポジトリを作る道具・隣の非公開のリポジトリ）への言及がある。`.githooks/`・`docs/structure.md`・`docs/requirements.md`・
  `tools.toml` も同じ。他の人の環境の AI は、無いファイルを探したり、無い道具の規約に従おうとしたりする
- チュートリアルの「AI と一緒に読む」はチャット型の AI（貼って聞く）だけを想定し、コマンドライン AI（Claude Code・Codex・Gemini CLI）が
  リポの中で命令を実行する使い方には触れていない
- 学ぶ人がコマンドライン AI に「全部やって」と頼むと、AI が黙って書き込み・組ませまで進め、本人は何も理解しないまま終わりうる。
  鍵・実機の MAC・周りの SSID を AI の画面やログに出す危険もある

## 決定

### 1. 学び方を 3 つに揃える（どれでも同じ章を進める）

| 読み方 | 何を使う | チュートリアル側で用意するもの |
|---|---|---|
| 一人で読む | チュートリアルとターミナルだけ | 各手順に**期待する画面の見本**、「確かめよう」に**答え**。AI が無くても詰まらない |
| チャット型の AI と読む | ChatGPT・Claude・Gemini など（貼って聞く） | 各節の終わりに**聞き方の例**（今の形を広げる） |
| コマンドライン AI と動かす | Claude Code・Codex・Gemini CLI（リポの中で動く） | 各節に**頼み方の例**。「実行して、何が起きたかを説明して」「この表示はどのファイルのどの関数が出している？」 |

- **AI は近道ではなく、説明役にする。** 頼み方の例は「やって」ではなく「一緒にやって、説明して」の形にする
- 各 🌳 の「手を動かして確かめる」は、AI があってもなくても同じ命令を本人が打つ（AI は結果の読み方とコードの場所を案内する）

### 2. `AGENTS.md` を「誰の環境でも通じる」内容だけにし、学ぶ人と作業するときの振る舞いを書く

- 公開する `AGENTS.md` に書くもの: 目的・命令・構成・注意（鍵・MAC・電波法・ポートの開き方・文言を変えたらチュートリアルも）と、
  **学ぶ人と作業するときの振る舞い**:
  - 実行する前に、何をするか・なぜかを短く言う。終わったら、何が起きたかと、それを担当するファイル・関数を示す
  - 対応するチュートリアルの節を示す（例: 「これは 2 章の doctor の読み方」）
  - **書き込み（`flash`）・組ませ直し・`PAIRCLEAR`・SD の削除は、本人の確認を取ってから**（元に戻せない・基板の中身が変わる）
  - 鍵・`PAIRSET` の行・実機の MAC・周りの SSID/BSSID を画面やファイルに出さない。記録（`data/`）をコミットしない
  - 答えを先に全部書かず、本人が打てる 1 行の命令を示す（学ぶ人が頼んだとき）
- 作者固有の規約は**リポの外**に置く。Claude Code は `CLAUDE.local.md`（git の対象外。Claude Code が自動で読む）、
  Codex・Gemini は作者のグローバル設定（作者の PC のホームの下）が既に同じ規約を読む
- 雛形由来の文書（`docs/structure.md`・`docs/requirements.md` の機微リポの節・`tools.toml`・`.githooks/`）は、
  キットに要る部分だけを残すか、作者用として外す。どれをどうするかは、その段で一覧にして利用者に確認する

### 3. 迷わないことを仕組みで確かめる

- テスト（CI）で、`AGENTS.md`・`README*`・`docs/tutorial/` に作者の PC の場所（ホームの下のパス・作者の運用のリポジトリの名前など）が無いことを検査する
- 公開前に、作者の設定の無い環境（別のユーザー・CI のコンテナなど）でコマンドライン AI にリポを読ませ、迷う所が無いか確かめる

## 根拠

- 一人で読める形を土台にすると、AI の有無・種類・料金に左右されない。AI はその上に足すもの
- 「AI に任せる」だけでは、学ぶ人に仕組みの理解が残らない。説明役として振る舞う指示を `AGENTS.md` に書けば、
  Claude Code・Codex・Gemini CLI のどれでも同じ振る舞いを期待できる（どれも `AGENTS.md` か、それを読み込む `CLAUDE.md`・`GEMINI.md` を読む）
- 作者の安全装置（PII ガード・機微リポ）は作者の環境でだけ意味がある。リポに残すと、他人の AI はそれを前提に動こうとして迷う。
  一方、作者が手放すと作者の側の守りが減るので、リポの外（`CLAUDE.local.md`・グローバル設定）へ移して保つ
- 費用: チュートリアルに 3 通りの案内が増え、命令・出力を変えたときに直す所が増える。CI の検査で場所の書き漏れだけは機械で止める

## 段階（各段の終わりに利用者に確認する）

1. 作者固有の設定の棚卸しと、`AGENTS.md`（公開用）・`CLAUDE.local.md`（作者用）への分割
2. `AGENTS.md` に「学ぶ人と作業するとき」の節。場所の検査をテストに足す
3. チュートリアルの「AI と一緒に読む」を 3 通りに広げ、0・1 章に頼み方の例と「確かめよう」の答えを足す（2〜6 章は書くときに同じ形で）
4. 作者の設定の無い環境で、AI が迷わないかを確かめる（公開前の点検の一部）
