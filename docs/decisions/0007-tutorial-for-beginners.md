# 0007. 対象をゼミに入ったばかりの初学者まで広げ、3 段のチュートリアルを足す

- ステータス: **採用**（2026-10-27）
- 対象: `docs/tutorial/`・`README.md`・`README.ja.md`・`docs/requirements.md`

## 背景

承認済みの計画（`docs/plans/2026-10-27-kit-extraction.md`）では、対象を「他の大学で Wi-Fi CSI を研究する学生」とし、
README は「ターミナル・git・Python・シリアルポートに慣れ、CSI が何かを知っている人」向けの手順書として書いた。

利用者から、**大学 3 年の後期にゼミに入り、マイコン・CSI・PC でのプログラミングを初めて始める人**
（スマホしか使ったことがない人も含む）でも使えるか、と問われた。今の README では、ターミナルの開き方・ポートとは何か・
CSI とは何か・記録の読み方・困ったときの直し方で止まる。

選択肢:

1. README を初学者向けに書き換える
2. README は手順書のまま残し、別に初学者向けのチュートリアルを足す
3. 対象を広げない（初学者には別の教材を案内する）

## 決定

**2 を採る。** `docs/tutorial/` に章立てのチュートリアルを置き、README の冒頭から案内する。

- 章: 0 PC の基本（ターミナル・uv・git・マイコン）／1 CSI とは／2 基板をつなぐ／3 書き込みと組ませる／4 モニタの読み方／
  5 記録とメタデータ／6 解析の入口／7 困ったとき・用語集
- 各章を 3 段にする: **🌱 ファーストタッチ**（スマホの経験に結びつけた比喩）→ **🌿 しくみ**（言葉と図）→
  **🌳 もう一段**（数式と、それを計算しているこのリポジトリのコード）。🌳 から ADR・ファームの README・`src/csikit/` へ進めるようにする
- 実機の要らない 0・1・7 を先に書く。2〜6 は画面の見本・記録のサンプルが要るので、実機で通す段と一緒に書く
- 比喩は理解の入口で、正確さの代わりではない。比喩の後には必ず正確な言い方を置き、比喩が当てはまらない所も書く
- 数値は「計算」「実測」「仮定」を区別して書く。実機で確かめていない困りごとは「想定」と書く

## 根拠

- README を初学者向けにすると、慣れた人には長すぎ、手順が埋もれる。手順書とチュートリアルは読む目的が違う
- 3 段にすると、同じページを、初めての人は 🌱 だけ、慣れてきたら 🌳 まで、と何度も読み返せる。
  🌳 がリポジトリのコードにつながるので、「使う」から「中を理解する・自分で変える」へ進む道ができる
- 対象を広げないと、キットを受け取ったゼミの初学者は、別の教材とこのキットの間を自分でつなぐ必要がある
- 費用: 文書が増え、ファーム・CLI を変えたときに直す所が増える。チュートリアルは命令の名前と画面の見本に依存するので、
  変えたらチュートリアルも直す（`AGENTS.md` の注意に書く）
