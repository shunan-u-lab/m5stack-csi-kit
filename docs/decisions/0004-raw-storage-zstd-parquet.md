# 0004. 記録は CSV を zstd で圧縮して保管し、Parquet は解析の途中の結果に使う

- ステータス: **採用**（2026-10-27。元の研究リポジトリで 2026-10-07 に決めた判断を引き継ぐ）
- 対象: `src/csikit/rawzst.py`・`src/csikit/io.py`・`scripts/raw_store.py`・`scripts/sd_fetch.py`

## 背景

- 長い記録は大きい。受信機の出力をそのまま書いた CSV（CSI は 16 進の文字・行ごとに CRC32）は
  1 時間 約 120 MB（約 2 MB/分）で、一晩で約 900 MB、毎晩なら 1 週間で約 6 GB になる
- 解析の読み込み（`io.load_rx_csv`）は 1 時間分で約 9 秒かかる
- 「Parquet にすれば小さく・速くなるか」を、1 時間分（120 MB）で比べた（2026-10-07 実測）

| 保存の方法 | 容量 | かかる時間 |
|---|---|---|
| CSV（そのまま） | 120 MB | 解析の読み込み 8.9 秒 |
| CSV を zstd -3 で圧縮 | 38.9 MB | 圧縮 0.8 秒 |
| CSV を zstd -19 で圧縮 | 25.9 MB | 圧縮 29 秒 |
| CSV を gzip -6 で圧縮 | 43.1 MB | 圧縮 3.6 秒 |
| Parquet（受信機の行をそのまま列に・CSI はバイト列・zstd 3） | 38.9 MB | 読み込み 0.1 秒 |
| Parquet（同・zstd 19） | 31.8 MB | 書き込み 10 秒・読み込み 0.1 秒 |

**容量は、Parquet にしても CSV を zstd で圧縮するのと変わらない**（強く圧縮すると CSV＋zstd の方が小さい）。
差が出るのは読み込みの速さと、必要な列だけを読めること。

## 決定

1. **記録は、CSV を zstd で圧縮した `<記録名>.csv.zst` で保管する**（既定の強さ 19）
   - 中身は元の CSV とバイト単位で同じ。行ごとの CRC と受信機の注記（`#` 行）もそのまま残る
   - 記録ツールは CSV を書く。圧縮は記録の後に `scripts/raw_store.py compress` で行う（記録中に止まっても、書けたところまでの CSV が残る）。
     SD カードからの取り込み（`sd_fetch.py`）は、取り込んだ直後に同じ手順で圧縮する
   - 圧縮は「書く → 展開し直して元と SHA-256 が一致するか確かめる → 改名」。元の CSV は `--delete-original` を付けたときだけ、
     一致を確かめた後に消す。直近 2 分以内に書き換えられた CSV は記録中とみなして飛ばす
   - `io.load_rx_csv` などの読み込みは `.csv.zst` をそのまま読む。記録名は `io.recording_name` で求める
     （`Path.stem` は `x.csv.zst` を `x.csv` にするので使わない）
2. **Parquet は、生の CSI の写しではなく、解析の途中の結果（1 秒ごとの指標・判定）の保存に使う**
   - 生の CSI の Parquet の写しは、圧縮した記録より大きく（下の結果）、読み込みを速くしても解析全体は 2 倍にしかならないため、常には置かない。
     同じ記録を何度も読み直すとき（機械学習で繰り返し読む等）だけ `scripts/raw_store.py parquet` で作り、終わったら消す
   - `io.load_rx` は拡張子で `.csv`・`.csv.zst`・`.parquet` を読み分ける

## 根拠

| 観点 | 判断 |
|---|---|
| 容量 | 保管は zstd の CSV で約 1/5（一晩 約 900 → 194 MB） |
| 元の形を残す | CSV のままなので CRC で壊れていないか確かめられ、読み込みを直せば読み直せる。変換した値だけを残すと、変換の誤りに気づけない |
| 速さ | 生の CSI の写しで読み込みは 1 時間分 約 9 秒 → 0.1 秒程度だが、解析全体は 2 倍どまり。時間がかかるのは 1 秒窓ごとの集計の計算 |
| 依存 | `zstandard`・`pyarrow`。Python 3.14 の標準の zstd は 3.10 で使えないため `zstandard` を使う |

実測（2026-10-07）:

- 9 本を圧縮: 902 MB → 194 MB・228 秒。9 本とも展開した中身が元と一致
- 一晩 8 本の生の CSI の Parquet の写し: 258 MB（**写しの方が圧縮した記録より大きい**。CSI を数値として持つため）
- 写しから連番と RSSI の列だけを読むと、一晩 263 万行で 0.25 秒（全列は 2.9 秒）
- 同じ解析を CSV・`.csv.zst`・Parquet から行うと 115 秒・117 秒・55 秒で、**3 通りとも出力は完全に一致**

見送ったこと:

- **記録ツールが最初から `.csv.zst` を書く**: 記録中に止まったときに末尾が読めなくなるおそれがあり、利点（後の圧縮の手間）が小さい
- **生データを Parquet だけにする**: 容量は小さくならず、元の形（CRC・注記）を失う
- **Parquet を自動で作る**: 読み込みのたびに書き込みが起きると、どこに何があるかが分かりにくくなる
