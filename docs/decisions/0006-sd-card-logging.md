# 0006. 受信機の出力を SD カードにも保存する（ボタンでセッション、失敗は自動で立て直す）

- ステータス: **採用**（2026-10-27。元の研究リポジトリで 2026-10-07〜10-11 に決めた判断を引き継ぐ）
- 対象: `firmware/csi-rx/src/sd_log.*`・`firmware/csi-rx/src/main.cpp`・`firmware/shared/CsiLcd`・`scripts/sd_fetch.py`

## 背景

受信機の出力は USB で PC に送って記録する。これでは PC がスリープすると記録が止まり、長時間の記録に PC を置き続ける必要がある。
M5Stack Basic には SD スロットがあるので、PC なしでも記録できるようにしたい。条件: ボタン 3 つで操作、既定は書き込みなし、
セッションごとに保存、SD から直接または USB 経由で PC に取り込める。**取りこぼしなど不安定にならないかを先に調べてから**実装した。

| 心配な点 | 調べた結果（2026-10-07） |
|---|---|
| SD と液晶の SPI バスの取り合い | M5Stack Basic は SD と液晶が同じ SPI バス（SCK 18・MOSI 23・MISO 19。CS は SD 4・液晶 14。M5GFX のソース）。液晶は別のタスクで描くので、鍵が要る |
| SD の書き込みの止まり | 40 KB/秒・60 秒: 4 KB の書き込み 平均 10.4 ms・**最大 29 ms**。ただし SD の規格上、書き込みの待ちは最大 250 ms（SDHC）まで許されている |
| メモリ | Wi-Fi を動かした状態で空き約 214 KB（連続の最大の塊 110 KB） |
| 速さ | 書き込み約 385 KB/s（必要な速さの約 10 倍）、読み出し 1,377 KB/s |
| PC への取り込み | ESP32 は USB メモリになれない。シリアル（921600 bps）の上限は約 90 KB/s |

## 決定

| 決定 | 理由 |
|---|---|
| 書き込みは**リングバッファ（48 KB）と専用のタスク**。受信の処理は行を置くだけで待たない。あふれた行は捨てて数え、液晶（`DROP`）と記録（`dropped_lines`）に出す | 40 KB/秒で約 1.2 秒分。規格の上限 250 ms の約 5 倍の余裕 |
| SPI バスは **1 つの鍵**で液晶の描画と SD の読み書きを交互にする | 同じバスを 2 つのタスクが使うため |
| **1 秒ごとに確定（flush）** | 電源を切っても失うのは最後の 1 秒まで |
| ボタン: A = 新しいセッション、B = 止める、C = 印（`# mark`。音と液晶で知らせる）。既定は書き込みなし。シリアルの `SDSTART`・`SDSTOP`・`SDMARK` も同じ | 押せたかが分からない問題を防ぐ。音は動画と時刻を合わせる手がかりにもなる |
| ファイルは `/CSI/S0001.csv` から番号順。中身はシリアルの出力と同じ形式で、先頭に見出し | 解析ツールがそのまま読める |
| **1 時間ごとに次の番号のファイルに切り替える**（行を落とさずに。各ファイルは単独で読める見出しつき） | FAT32 は 1 ファイル 4 GiB まで（exFAT は無効）。壊れたときの被害も小さくなる |
| 時刻: 受信機の NVS に Wi-Fi を設定しておけば、**起動時に NTP で時刻を取り**、切断してから受信を始める。PC からの `TIME` でも教えられる | M5Stack Basic に時計の電池は無い。受信を始める前なので CSI を止めない |
| Wi-Fi の名前とパスワードは**受信機の NVS**に置く（`WIFISET`・`sd_fetch.py wifi`）。ファームに埋め込まない | ビルドの成果物にパスワードを残さない。`WIFICLEAR` で消せる |
| **セッション中に再起動したら自動で再開する**（B・`SDSTOP` で止めたときだけ再開しない） | 既定が「書き込みなし」なので、停電・ウォッチドッグで再起動すると何も残らなかった |
| **書き込みの失敗を検知し、自動で立て直す**: 確定の後にカード上の長さを読み直して比べる。一瞬の失敗は同じセクタを最大 3 回書き直す。それでも駄目ならセッションを打ち切り、① 新しいセッションを開く → ② カードを付け直す → ③ 5 秒ごとに ② を繰り返す | FatFs は一度失敗したファイルを閉じるまで使えなくする。立て直さないと、それ以後が丸ごと失われる（下の「起きたこと」） |
| 失敗・再開・立て直しを**受信機の NVS に「出来事」**として残す（直近 16 件・`SDEVENTS`） | カードが書けなくても残り、後から読める |
| 液晶: 失敗は赤い `SD ERROR`、立て直し中は `SD RECOVERING`、立て直した後は帯に回数 | PC なしでも、画面を見れば何が起きたかが分かる |
| 取り込み: `scripts/sd_fetch.py`。USB 経由は **4 KB の塊ずつ確認しながら**送る（受信機は PC の返事 `K`・`R`・`Q` を待つ）。カード読み取り器からは `import-dir`。取り込んだら `.csv.zst` に圧縮する（0004） | 流し続ける転送では、2.1 MB でときどき塊が壊れた（PC 側の取りこぼしとみられる） |

見送ったこと:

- **SD に直接 `.csv.zst` で書く**: 圧縮の CPU とメモリが要り、書きかけで止まると読めなくなる
- **別のログファイル**: カードが書けない間は、別のファイルにも書けない。健康状態は記録の中の `# sdstat`（毎秒）と NVS の出来事に残す
- **立て直しの最後の手段としての自動の再起動**: 付け直しと効き目が同じで、再起動を繰り返すおそれがある
- **電圧の測定**: 本体に測る回路が無い（電源 IC の IP5306 も電圧を出さない）

## 根拠

### 実測（M5Stack Basic・8 GB の SDHC）

- 60 秒: 書き込みの最大 21 ms・バッファの最大 2.3 KB（48 KB 中）・取りこぼし 0。
  **SD のファイルの CSI 行（6,174 行）は、同じ時間にシリアルへ出た行と、行数・中身・順番とも完全に一致**
- 10 分: 20.3 MB・取りこぼし 0・書き込みの最大 94 ms・バッファの最大 5.0 KB（約 10 倍の余裕）。60 秒では見えなかった長めの止まりが出た
- USB 経由の取り込み 2.09 MB を 32 秒（66 KB/s）
- 1 時間ごとの切り替え（試験で 60 秒ごと・200 秒）: 4 本に分かれ、切り替え 1 回は 68〜118 ms・取りこぼし 0。
  境目の 3 か所とも送信機の連番の差は 1（抜けた行はない）
- 記録中にカードを抜いて約 4 分後に差し戻す: 付け直しの 47 回目で新しいセッションに再開。失ったのはカードが無かった間だけ
- 書き込みをわざと失敗させる試験（`SDFAULT`）: 1〜3 回の失敗は書き直しで救われ、同じファイルに書き続けた。
  4 回以上は立て直しになり、1 回で約 0.4〜0.5 秒分を失う

### 起きたこと（立て直しを入れた理由）

立て直しを入れる前、PC なしの記録が約 830 秒で途切れた。液晶は記録中のまま量が増え続けたが、カードに残ったのは 27.9 MB だけだった。

- FatFs は一度書き込みに失敗したファイルを閉じるまで使えなくする（以後の書き込みはカードに触れずに失敗を返す）
- ファイルには 4 KB のバッファがあり、書き込みの多くはバッファに写すだけで「成功」を返す。**画面の量は書けたつもりの量だった**
- 失敗はシリアルにしか出しておらず、立て直す作りも無かった

→ 直接の原因は「1 回の失敗に気づかず、立て直さない作り」。最初の 1 回のきっかけは未解決（下）。
その後、PC 給電で自然に起きた失敗（10 ms で失敗・カードは直後に応答）は、立て直しで 95 ms 後に新しいセッションへ再開した。

## 限界・注意

- **最初の失敗のきっかけは未解決。** 候補（推測）: SPI の速さ（25 MHz。液晶と配線を共有し長い）・カードの個体・電源の揺れ
- 記録中にカードを抜くと、基板上の USB 変換チップが止まる・付き直すことがあった（本体は動き続けた。3 回中 2 回）
- PC からポートを開くと受信機がリセットされることがある。SD に記録中だと、自動の再開で新しいセッションに分かれる
  （`csikit` は DTR/RTS を下げて開く。記録用の `capture_csi.py` は既定で受信機をリセットするので、SD の記録中は `--no-reset`）
- NVS は暗号化していない。基板を手にした人は Wi-Fi のパスワードを読み出しうる。人に渡す・返す前に `WIFICLEAR`
- 自動の再開は「止め忘れ」も再開する。B を押さずに電源を抜くと、次に電源を入れたとき記録が始まる（液晶の `REC` で分かる）
- 一晩（8 時間）の書き込みの止まりの最大は未測定。`# sdstat` の `write_max_ms`・`buffer_high` で見張る
- 1 時間 約 120 MB は USB 経由で約 30 分かかる。長い記録はカード読み取り器の方が速い
