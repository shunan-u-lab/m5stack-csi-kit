# 0009. 最終的な公開先を GitHub の組織 shunan-u-lab にし、周南公立大学の大学院生が公開するものとする

- ステータス: **採用**（2026-10-28。方向のみ。移す・公開に切り替える操作は、その時点で利用者に確認する）
- 対象: リポジトリの置き場・`README*`・`DISCLAIMER*`・`LICENSE*`・`docs/tutorial/`
- 関連: 計画 `docs/plans/2026-10-27-kit-extraction.md`（公開は点検と貸与元への連絡の後）、ADR 0008

## 背景

今は作者の個人アカウントに private で置いている。
文書は「個人が作った道具」と書き、クローンの URL・リリースの URL・著作権表示は個人アカウントの名前になっている。

利用者（作者）の方針（2026-10-28）: **最終的には GitHub の組織 `shunan-u-lab` の上で public として公開し、
周南公立大学の大学院生が公開している内容とする。**

## 決定

- 公開先は `shunan-u-lab/m5stack-csi-kit`（public）。今の private のリポを組織へ移す（transfer）か、組織に作って push するかは、その時点で決める
- 公開する人の表し方は「**周南公立大学 大学院生**」。実名は書かない（このリポの規約。`AGENTS.md`）
- 順番は計画のとおり: 公開前の点検（ADR 0008 の 4 段目を含む）→ 機材の貸与元の先生方へ連絡 → 組織へ移す → public に切り替える。
  移す・切り替えるは外へ出る操作なので、それぞれの時点で利用者に確認する

## 移すときに変えるもの（今は変えない）

| 場所 | 今 | 変える先 |
|---|---|---|
| クローンの URL（`README.md`・`README.en.md`・`docs/tutorial/00_pc_basics.md`） | 個人アカウントの URL | `github.com/shunan-u-lab/m5stack-csi-kit` |
| リリースの URL（`README.md`・`README.en.md`） | 同上 `/releases` | 同上 |
| 公開する人の表し方（`README*` の冒頭のおことわり・`DISCLAIMER*`・`docs/tutorial/README.md`） | 「個人が作った」「one person」 | 「周南公立大学の大学院生が公開」。下の「決めること」を反映して書く |
| 著作権表示（`LICENSE`・`LICENSE-CODE`・`LICENSE-DOCS`） | 個人アカウントの名前 | 下の「決めること」 |

- 移した後、GitHub は古い URL から転送するが、文書は新しい URL に揃える
- 古い URL が残っていないことは、移す時にテストで検査する（ADR 0008 の場所の検査と同じ形）

## 移す前に決めること（利用者）

1. **大学の公式なものか、大学院生が個人として公開するものか。** おことわりの書き方が変わる
   （公式でないなら「大学・研究室の公式なものではない」と書く）。組織 `shunan-u-lab` の運用の決まり（誰が管理者か・公開してよい範囲）も確かめる
2. **著作権者の名前。** 個人のアカウント名のままにするか、「周南公立大学 大学院生」などにするか
3. **移し方。** transfer（履歴・PR・リリースごと移る）か、組織に新しく作って push するか。
   今の履歴には開発の経緯（元の研究のリポジトリ名・実機の呼び名）が残る（ADR 0008 の 4 段目で扱う）

## 作者の環境への影響（作者の手元で対応する）

- 作者の手元のガード（`.githooks/`）を入れる仕組みは、リモートの URL で「自分のリポか」を見分けている。
  移した後は URL が `shunan-u-lab` になるので、作者の側の設定に組織名を足さないと、ガードの対象から外れるおそれがある
  （詳細は `CLAUDE.local.md`。このリポでは変えない）

## 根拠

- 研究室の組織に置くと、後輩・他大学の学生が見つけやすく、作者が卒業した後も引き継げる
- 実名を書かない規約は保ったまま、所属で「誰が公開したか」を示せる
- 移す・公開するは取り消しにくい（一度 public にした中身は複製されうる）ので、決めることを先に並べ、操作は確認してから行う

## 追記（2026-10-28）: 公開する人の表示

利用者（作者本人）が決めた: 公開する人の表示は、**所属・課程と本人の名前**とする（文言は `README*`・`DISCLAIMER*`・`LICENSE*` の公開者の表示を見る）。

- 上の「実名は書かない」を、**公開者本人の表示に限って**改める。書く場所は公開者の表示（`README*` のおことわり・`DISCLAIMER*`・`LICENSE*` の著作権表示）だけ
- それ以外（記録・例・試験の記録・作業の記録）では、これまでどおり実名・連絡先を書かない。本人以外の実名（先生方・協力者など）は書かない
- 文言を入れるのは移すときと同じ時点（「移すときに変えるもの」の表に従う）。英語の表記は、そのときに本人に確認する
- 「移す前に決めること」の 2（著作権者の名前）はこの表示に揃える案を、移すときに確認する。1（公式か個人か）と 3（移し方）は未決

## 追記（2026-10-28）: 公開するリポは新しく作り、公開後はそちらを正にする

利用者が決めた: **`shunan-u-lab/m5stack-csi-kit` を新しい履歴で作り、公開後の開発はそちらで続ける**（案 A）。
開発に使ってきた個人アカウントのリポから書き出し続ける形（案 B）は採らない。

- 理由: 元の研究のリポジトリもあり、3 つを並行して管理するのは負担が大きい。公開リポを正にすれば、
  学生からの Issue・PR をそのまま受けられ、二重管理にならない。新しい履歴なので、元の研究の名前・旧称・消した作者用ファイルが公開の履歴に残らない
- 書き出しは手作業でせず、**許可リストで写し、作者の PC の場所・実機の MAC・旧称が無いかを検査して、問題があれば止めるスクリプト**で 1 回行う
- 「移す前に決めること」の 3（移し方）はこれで決まり。1・2・英語の表記・組織の運用の決まりは未決
- 作者だけの注意（実機の呼び名と元の研究との関係など）は、公開リポを手元に置いたときの `CLAUDE.local.md`（git の対象外）に移す
- このリポの公開後の扱い（凍結か削除か）は、公開リポで一通り動くのを確かめてから決める（`docs/tasks/current.md`）

## 追記（2026-10-28）: 個人として公開する・確認の順番

利用者が決めた:

- **大学の組織（`shunan-u-lab`）の上で、大学院生が個人として公開する。** 大学・研究室の公式なものではない。
  おことわり（`DISCLAIMER*`）には「大学・研究室の公式なものではない」と書く（「移す前に決めること」の 1 はこれで決まり）
- **Windows・Mac の実機での確認は、公開リポを public にした後に、public からクローンして行う。**
  それまで README の「動作確認の状況」は Windows・Mac を「未確認」のままにする
- **機材の貸与元の先生方には、公開した後に確認していただく。** 上の「決定」の順番（貸与元へ連絡 → 移す → public）を、
  移す → public → 貸与元に確認、に改める。確認で直すことが出たら、公開リポで直す
- 未決: 著作権者の名前（公開者の表示に揃える案）・英語の表記・組織の運用の決まり（誰が管理者か・公開してよい範囲）

## 追記（2026-10-28）: 公開リポへ写すときに中立に直したもの

公開リポには ADR と試験の記録も入れる（README・チュートリアル・ファームのコメントからリンクしているため）。
写す前に、元の研究のリポジトリの名前・実機の旧称・作者の PC の場所・作者のアカウント名を、一般的な書き方に直した
（ADR 0002・0008・0009、試験の記録 1 件）。判断の中身は変えていない。

## 追記（2026-10-29）: 引用の情報（CITATION.cff）にも公開者の表示を書く

論文・発表で引用できるように、リポ直下に `CITATION.cff` を置き、`README*` に「引用のしかた」の節を足した。
`CITATION.cff` には著者として公開者本人の名前と所属を書く（`README.en.md` のおことわり・`LICENSE*` と同じ英語の表記）。

- 公開者の表示を書いてよい場所（2026-10-28 の追記）に `CITATION.cff` を加える。書くのは名前と所属だけで、連絡先（メールアドレス・ORCID など）は書かない
- `CITATION.cff` の版は `pyproject.toml` の版と同じにする（`tests/test_public_docs.py` で検査する）
- DOI（Zenodo との連携）は外部のサービスへの登録なので、ここでは決めない
