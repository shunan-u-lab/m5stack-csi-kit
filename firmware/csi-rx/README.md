# csi-rx — CSI 受信機（M5Stack Basic）

ルーターに接続せず、起動時は ch11（シリアルの命令で ch1〜13 に切り替えられる）で、組んだ送信機（`firmware/csi-tx`）の
パケットだけから CSI を取り、シリアル（921600 bps）へ 1 行ずつ出す。同じ出力を SD カードにも保存できる（PC なしの記録）。

## 書き込みと組の設定

普段は `csikit flash` を使う（ビルド済みの `.bin` を書き、送信機と組ませる）。ファームを変えたいときだけ自分でビルドする:

```sh
cd firmware/csi-rx
pio run
pio run -t upload --upload-port <ポート>   # 送信機を書き潰さないよう、先に WHO で役割を確かめる
pio device monitor -b 921600
```

書き込んだだけでは**組（送信機の MAC と制御の鍵）が未設定**で、どの送信機のパケットも拾わない。
液晶に黄色の `NOT PAIRED`、起動時の表示に `paired=0` と `# not_paired` が出る。
組はシリアルの `PAIRSET` で NVS に置く（`csikit flash` が両方の M5Stack Basic に送る。判断は `docs/decisions/0002`）。

**ポートを開くと再起動することがある。** USB 変換チップ（CH9102）の DTR/RTS が本体のリセットにつながっているため、
開き方によっては再起動し、受信機は時刻の取得（NTP。手元の Wi-Fi を設定していれば）を待つ間しばらく黙る
（設定済みで約 16 秒）。とくに「開く前に DTR/RTS を下げておく」形は、Linux では毎回再起動する（開いた瞬間に DTR だけが
先に下がるため。2026-10-28 に 3 回中 3 回）。`csikit` は開いてから RTS → DTR の順に下げ、再起動させない（3 回中 0 回）。

## シリアルの命令

921600 bps で 1 行ずつ送る（改行 `\n` で区切る。最大 232 文字）。応答はすべて `#` 行なので、
記録中に送っても `io.load_rx_csv` は注記として読み飛ばす。

| 命令 | 応答（成功） | 内容 |
|---|---|---|
| `WHO` | `# who role=rx mac=<MAC> channel=<n> format=3 tx_mac=<送信機の MAC> relay=1 pico=0 auth=<on/off_no_key> tx_power_dbm=<dBm> fw=<版> paired=<0/1>` | 再起動せずに、この M5Stack Basic かどうかと今の設定を確かめる |
| `PAIRSET <送信機の MAC 12 桁> <鍵 32 桁>` | `# ack cmd=PAIRSET restarting` | 組を NVS に置いて再起動する。応答に鍵は出さない |
| `PAIRCLEAR` | `# ack cmd=PAIRCLEAR restarting` | 組を消して再起動する（機材を返す・人に渡す前） |
| `CH <1〜13>` | `# ack cmd=CH channel=<n> relay=ok acked=<0/1> attempts=<回数> …` | **送信機にも無線で伝えて** 2 台を切り替える（下） |
| `CHLOCAL <1〜13>` | `# ack cmd=CHLOCAL channel=<n>` | 自分だけ切り替える（送信機はシリアルで別に切り替える使い方） |
| `TXP <2〜20>` | `# ack cmd=TXP want_dbm=<指定> dbm=<読み戻し>` | 受信機自身の送信出力（制御パケットだけ）の上限 [dBm] |
| `TXPS <2〜20>` | `# ack cmd=TXPS want_dbm=<指定> dbm=<実際の値>` | **送信機の**出力を無線で変える（確認の手順つき。`firmware/csi-tx/README.md`） |
| `TXREBOOT` | `# ack cmd=TXREBOOT acked=<0/1> back=<0/1>` | 送信機を無線で再起動する（`back`: 送信機の連番が 0 近くに戻ってまた届いた） |
| `REBOOT` | `# ack cmd=REBOOT restarting` | 受信機自身を再起動する（次の起動の表示は `boot=sw`） |
| `WDTTEST` | `# wdt_test block_ms=…` | わざと loop を止めてウォッチドッグを確かめる（5 秒ほどで再起動する） |
| `OTHERS` | `# other mac=<送信元> n=<CSI の数> …` と `# others sources=… overflow=…` | 送信機以外から来た CSI を送信元ごとに数えた表を出してリセットする（最大 8 送信元） |
| `BSCAN [dwell_ms]` | チャンネルごとに `# beacon ch=<n> bssid=<BSSID> … ssid_hex=<SSID の 16 進>`、最後に `# bscan done back_to=<n> result=ok` | ch1〜13 を自分で回り（既定 1500 ms ずつ・200〜10000）、聞こえたビーコンを BSSID ごとに数えて元のチャンネルに戻る。走査の間は CSI を出さず、番犬も働かない。PC からは `scripts/beacon_scan.py`（`--mask` で BSSID・SSID を伏せる） |
| `ALLCSI ON` / `ALLCSI OFF` | `# ack cmd=ALLCSI on=<0/1> rows=<他の送信元の行の数> channel=<n>` | **テスト用。** オンの間は送信機以外から来た CSI も出す（`<tx>` に実際の送信元・`<seq>` は -1）。番犬が止まる。SD に記録中はオンにできない。再起動でオフに戻る |
| `BATT` | `# batt ok=1 charging=… full=… level_pct=… …` | 電源 IC（IP5306）の状態（`firmware/shared/CsiLcd/src/CsiPower.h`） |

SD・時刻・Wi-Fi の命令は下の「SD カードへの保存」。

- 失敗は `# err cmd=<命令> reason=<理由>`（範囲外は `out_of_range`、読み戻しの不一致は `verify_failed`、
  送信機が範囲外と答えた `tx_nack`、了解が来ず送信機も動いていない `tx_no_ack`、見失った `no_link`・`lost_link`、
  組が未設定の `no_key`、送信機の合言葉をまだ読めていない `no_nonce`、組の形の誤り `bad_mac`・`bad_key`、
  知らない命令は `unknown`、長すぎる行は `too_long`）。受信は止めない
- 起動時は `WIFI_CHANNEL`（ch11）。切り替えたチャンネルは電源を切ると戻る
- 国は `"JP"` に明示する（`esp_wifi_set_country_code`。既定は `"CN"`）。日本では ch1〜13 が OFDM で使える
  （ch14 は DSSS のみで 11n は使えない）。国の設定は M5Stack Basic のフラッシュにも保存される（ESP-IDF の仕様）

### `CH n` の手順

送信機に署名付きの `SET_CH n` を送る（了解が 0.3 秒来なければ 3 回まで）→ 自分も切り替える →
送信機のパケットが新しいチャンネルで 0.5 秒以内に届くのを確かめてから `ack` を返す。
了解だけが失われた場合（送信機はもう移った）は、元のチャンネルから送信機が消えたことで判断して進む
（`acked=0`）。新しいチャンネルで送信機が見つからなければ、元のチャンネル → 起動時のチャンネルの順に戻って
`# err cmd=CH reason=no_link|lost_link` を返す。

- 1 秒ごとに送信機へ合図（`KEEPALIVE`）を送る。送信機は合図が 4 秒途絶えると ch11 に戻る
- **番犬**: 起動時のチャンネル以外で送信機のパケットが 5 秒途絶えたら ch11 に戻る（`# watchdog no_frames_ms=...`）
- 送信機の了解（制御パケット）は連番の対応づけから除く。記録中は送信しないので CSI 行には混ざらない
- 実測: 13 チャンネル × 2 周で 26/26 成功・了解の取りこぼし 0・1 回あたり約 0.1 秒

### 制御パケットの署名

組の鍵で署名する（`firmware/shared/CsiAuth`。詳細は `firmware/csi-tx/README.md` の「署名」）。組が未設定なら送信機に
無線で命令せず、`CH` は `# err cmd=CH reason=no_key`（`CHLOCAL` は使える）。署名の合わない了解は
`# stats` の `ctrl_bad` に数えて捨てる。

## 液晶の表示

描画は別タスク（コア 0・1 秒ごと。`firmware/shared/CsiLcd`・M5GFX 0.1.17）で、CSI の書き出しは待たない
（液晶を足しても `dropped=0` を確認）。

| 行 | 内容 |
|---|---|
| 上の帯 | 機器番号（`R1`）と、役割・ファームウェアの版 |
| 状態の帯 | 緑 `RX from T1` / 黄 `NOT PAIRED`（組が未設定）・`LOW RATE`（50 Hz 未満）/ 赤 `NO SIGNAL`（受信なし）。右端に時計（時刻を知らなければ `--:--`） |
| 本文 | MAC・チャンネルと受信レート・欠け率（`loss` 直近 1 秒 / `all` 起動から）・RSSI と送信機の出力・`dropped` と中継の成功/失敗・起動からの時間・SD の状態 |

- 欠け率はプロミスキャス側で読んだ連番の飛びから数える（1000 を超える飛び・逆戻りは送信機の再起動とみなして数えない）
- 画面の明るさはボタン C の長押し（送信機と同じ。`CsiButtons.h`）。消灯中は、どのボタンも最初の 1 回は画面を点けるだけ
  （暗い中での押し間違いで記録を止めないように）

## SD カードへの保存（判断は `docs/decisions/0006`）

SD カード（FAT32）に、シリアルと同じ出力をセッションごとに保存する。

| 操作 | ボタン | シリアル |
|---|---|---|
| 新しいセッションを始める | A（左） | `SDSTART` |
| 止める | B（中） | `SDSTOP` |
| 印を付ける（`# mark label=…`） | C（右）を短く | `SDMARK [ラベル]` |
| 画面の明るさ（普通 → 暗い → 消灯） | C を 1 秒押し続ける | — |

| 命令 | 内容 |
|---|---|
| `SDLS` | `/CSI` のファイルの一覧 → `# sd file name=S0001.csv bytes=…`（セッション外だけ） |
| `SDGET <名前> [位置]` | ファイルを送る（4 KB の塊ごとに PC の返事 `K` 次へ・`R` もう一度・`Q` やめる を待つ。セッション外だけ） |
| `SDRM <名前>` | 消す。消したファイルの大きさと消す前後の空きを返す（セッション外だけ） |
| `SDINFO` | カードの種類・容量・空き |
| `SDROTATE <秒>` | ファイルを切り替える間隔（0 = 切り替えない） |
| `SDEVENTS` / `SDEVENTS CLEAR` | NVS に残した出来事（失敗・再開）を読む / 読んで消す |
| `SDFAULT <0〜10>` | 試験用。次の n 回の書き込みをわざと失敗させる |
| `TIME <unix> <UTC からの差 秒>` | 時刻を教える（再起動すると消える） |
| `WIFISET <名前の 16 進> <パスワードの 16 進（空なら ->）> <UTC からの差 秒>` | 時刻の取得に使う Wi-Fi を NVS に置く（応答に中身は出さない。次の起動から使う） |
| `WIFICLEAR` | Wi-Fi の設定を消す（機材を返す・人に渡す前） |

- **印を付けたときの知らせ**: 記録中は短く高い音（2 kHz・0.12 秒）が鳴り、状態の帯が 2 秒黄色の `MARK n OK`
  （n はセッションで何番目）。記録していなければ低く長い音（500 Hz・0.4 秒）と赤の `MARK: NOT REC` で、印は SD に残らない。
  音は行を書く直前に鳴らし始めるので、動画の音声から印の時刻を拾える
- 既定は書き込みなし。ファイルは `/CSI/S0001.csv` から番号順。長いセッションは 1 時間ごとに次の番号のファイルに切り替える
  （FAT32 の 4 GiB の上限と、壊れたときの被害を小さくするため）
- 記録中は液晶の 6 行目に `REC S0003 1234.5MB` を**赤字**で、5 行目の右端に経過を出す。止めている間は `SD idle 7.2GB`、カードが無ければ `SD none`
- **電源を切る・カードを抜く前は B で止める**（1 秒ごとに確定しているが、書きかけの最後の 1 秒は消えうる）
- **書き込みの失敗**: 状態の帯が赤い `SD ERROR`。一瞬の失敗は同じセクタを最大 3 回書き直して救う。
  それでも失敗したら**自動で立て直す**（新しいセッションを開く → カードを付け直す → 5 秒ごとに繰り返す）。
  立て直したセッションの先頭に `# sd recover from=… reason=…` を書き、NVS に出来事を残す
- **自動再開**: セッション中に再起動したら（停電・ウォッチドッグ・リセット）、起動後に新しいセッションを始める
  （`# sd resume boot=<理由>`。止まっていた間のデータは無い）。B・`SDSTOP` で止めたときだけ再開しない。
  電源を抜く前に B を押し忘れると、次に電源を入れたときに記録が始まる（液晶の `REC` で分かる）
- **時刻（NTP）**: `WIFISET` で Wi-Fi を設定しておくと、起動時に一度つないで NTP（`ntp.nict.jp`・`time.google.com`）で
  時刻を取り、切断してから受信を始める（`# ntp ok=1 now=…`。取れなければ `ok=0 reason=…` で時刻なしのまま続ける）。
  2.4 GHz の Wi-Fi に限る。時刻を取れなかったセッションは、取り込み時に開始時刻を手で与える
- 取り込み: `uv run python scripts/sd_fetch.py list` / `get S0003.csv`（USB 経由・約 66 KB/s）/
  `import-dir <カードの CSI フォルダ>`（カード読み取り器）

実測: 60 秒の記録で SD の CSI 行が同じ時間のシリアルの出力と完全に一致。10 分の記録で 20.3 MB・取りこぼし 0・
書き込みの最大 94 ms・バッファの最大 5.0 KB（48 KB 中）。記録中にカードを抜いて約 4 分後に差し戻すと、
付け直しの段で新しいセッションに再開した（失ったのはカードが無かった間だけ）。
カードの抜き差しで USB 変換チップが付き直すことがあった（本体は動き続けた。電源の揺れの疑い）。

## 出力（format=3）

`#` で始まる行は注記（起動時の設定・1 秒ごとの `# stats`・命令の応答）。本体は次の形:

```
CSI,<rx_us>,<tx>,<seq>,<rssi_dbm>,<noise_floor_dbm>,<channel>,<secondary>,<sig_mode>,<mcs>,<cwb>,<stbc>,<sgi>,<first_word_invalid>,<ltf>,<len>,<hex>*<crc32>
```

| 列 | 内容 |
|---|---|
| `rx_us` | 受信時刻 [µs]（受信機ローカル。約 71.6 分で 32bit が一周する） |
| `tx` | 送信元の MAC（12 桁の 16 進） |
| `seq` | 送信機の連番（`firmware/csi-tx` のペイロード）。対応が取れなければ `-1`。**複数の受信機の行を揃える鍵** |
| `rssi_dbm` / `noise_floor_dbm` | RSSI・雑音レベル [dBm] |
| `sig_mode` / `mcs` / `cwb` / `stbc` / `sgi` | 0/1: 11bg/HT、MCS、0/1: 20/40 MHz、STBC、GI |
| `first_word_invalid` | 1 なら先頭 4 byte（2 サブキャリア分）が無効 |
| `ltf` | どの区間の CSI か。11n は HT-LTF だけ（`htltf`）、11g は `lltf`、それ以外は `raw` |
| `len` | CSI 生データ長 [byte]（1 区間 = 128 バイト = 64 サブキャリア） |
| `<hex>` | CSI 生データ。int8 を 2 桁の 16 進（2 の補数）で連結。**2 byte で 1 サブキャリア、[虚部, 実部] の順** |
| `<crc32>` | `*` より前の全体の CRC32（`zlib.crc32` と同じ）。不一致の行は捨てる |

- 見出しに `# tx id=<番号> mac=<MAC> name=<機種名>` を出す。番号 0 が組んだ送信機（`primary=1`）
- `# stats` の `dropped` は受信機内のキュー溢れ（シリアルが追いつかない）、`other` は送信機以外からの CSI（出力しない）、
  `frames` はプロミスキャス側で受けた送信機のフレーム、`parse_fail` はそのうち ESP-NOW として読めなかった数、
  `seq_unmatched` は連番を付けられなかった CSI 行
- 1 秒ごとの `# stats` に自分と送信機のチップの温度（`temp_c`・`peer_temp_c`。内蔵センサーの目安で、
  Wi-Fi の発熱で室温より 20〜30 ℃ 高い）。セッションの先頭に `# env …`（温度・液晶の明るさ・カード・電源 IC）
- 読み込み: `csikit.io.load_rx_csv(path)`。`format=1`・`format=2`（古い形式）も列数で見分けて読む
- 受信機内に Raspberry Pi Pico W を 2 台目の送信機として受けるコードが残っているが、キットでは使わない
  （接続は既定で切ってある。`CSI_PICO_RELAY=0`）

### 連番の対応づけ

CSI コールバックにはパケットの中身が渡らない。プロミスキャス受信で ESP-NOW フレームを読み、
**受信時刻（`rx_ctrl.timestamp`）が完全に一致する** CSI 行に連番を付ける。

- 同じパケットの 2 つの受信時刻は一致する（実測で `seq_dt_max_us=0`、2854 行すべて対応）
- 近傍（±2 ms）を許すと、別パケットの連番を付ける恐れがある。誤った連番より `-1` の方が安全なので一致のみにした
- 合わなければ `parse_fail` に数える。起動後最初の送信機フレームは `# first_frame=<16 進>` として 1 度だけ出る

## 実測（M5Stack Basic 2 台・同じ机の上）

| 項目 | 値 |
|---|---|
| 実効レート | 99.9 Hz（12 秒・1200 行） |
| 欠番 | 4 / 1203 |
| 受信機内の取りこぼし | `dropped=0`（CH9102 経由の 921600 bps でも） |
| RSSI | −56〜−55 dBm |
| CRC 不一致 | 1 行（読み始めの途中の行と思われる。未確認） |

## 未解決

- **振幅のスケール**: `manu_scale=false`（自動）のため、パケットごとに倍率が変わりうる。
  振幅の絶対値を比べる解析では影響を確かめる必要がある
- **受信間隔のばらつき**: 連番が 1 つ違いでも受信間隔は 4.9〜15.1 ms になることがある（送信側の遅れか空き待ちと考えられる。未切り分け）。
  `rx_us` を等間隔の時計とみなすと周波数解析が歪む。連番（= 送信予定時刻 `seq × 10 ms`）を時間軸に
  使うか、受信時刻で補間して等間隔にする必要がある
